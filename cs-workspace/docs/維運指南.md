# CS Workspace 維運指南（IT）

本文件是給 IT／維運人員的技術說明。客服日常使用只需看 [README](../README.md)，這裡的內容客服不需要理解。

---

## 系統架構

![系統架構圖](img/01-architecture.png)

憑證全部個人化，存在各使用者自己的環境變數、ADC 檔、Git Credential Manager 裡。個人 PAT 一魚兩吃：gitlab-mcp 的 API 呼叫、marketplace 的 clone 都用同一組。

安裝為什麼拆兩階段：UAC 提權常會用另一組管理員帳號，凡是「屬於某個使用者」的東西（憑證、per-user 安裝的軟體）都必須由客服本人的 session 執行，否則會落到錯的 profile。所以階段 1 只裝全機共用的軟體，其餘全部留給階段 2。

> 流程圖的正本是 Claude Design 畫布（<https://claude.ai/code/artifact/c9425ee3-4809-4639-bcfe-412e0b3f6abf>）。改圖請在畫布上改完，重新匯出覆蓋 `docs/img/`。

## 專案特色

- **一鍵安裝。** 客服全程不用懂技術細節，兩個 bat 檔跑完就能上工。
- **憑證無痛設定。** 精靈逐項引導填 token，GCP 只要登入一次 Google 帳號。
- **全機零共用祕密。** 每個人用自己的憑證，離職停權只要停個人帳號。動作都掛在個人帳號上，GitLab 與 GCP 的稽核 log 追得到是誰做的。
- **更新極簡。** IT 把 plugin 合進 main，通知客服雙擊 `upgrade.bat` 即可。出問題就 revert，客服再跑一次就回滾。
- **白名單集中管控。** 客服能用哪些工具，由一份 `cs-settings-template.json` 決定。
- **知識庫即時生效。** SOP 存在魔鏡，改一次全體客服馬上查得到，不會各台漂移。
- **權限最小化。** GCP 只給 Logging Viewer，marketplace 對客服唯讀，客服端沒有能改壞系統的權限。

## 佈署前必填參數

| 位置 | 項目 |
|---|---|
| `cs-config.json` | 固定參數的 SSOT（隨 zip 附帶，不含祕密）：GitLab base URL、marketplace 追蹤分支與名稱、本 repo path、預設 GCP 專案。改參數就改這份檔案再發新版。 |
| `cs-settings-template.json` | marketplace 的 git `url`（要與 `cs-config.json` 一致）與 plugin 白名單。 |

## 帳號與權限

- 每位客服發自架 GitLab 帳號＋PAT（scope 選 `api`）。這組 PAT 同時給 gitlab-mcp 和 marketplace 用。
- 把客服帳號加進可讀 GFF-Marketplace 的 group（Reporter 即可）。
- 每位客服的公司 Google 帳號，在目標 GCP 專案開 `roles/logging.viewer`。
- 魔鏡的 HTTP endpoint 要能從客服網段連到，並發 API key。
- 客服的 Anthropic 帳號（團隊方案席次）。

## 更新機制

![日常更新流程](img/04-update.png)

分三塊，各自獨立：

1. **Claude Desktop app** 內建自動更新，不用管。
2. **plugin 內容**走 `upgrade.bat`。它會先更新 marketplace，再重裝白名單 plugin 確保為最新。發版節奏由通知控制：plugin 合進 main、RD 端自用驗證過，IT 才通知客服更新。回滾就在 marketplace revert，請客服再跑一次。
3. **白名單與受管設定**的 SSOT 是本 repo 的 `cs-settings-template.json`。改白名單合進 main，客服下次跑 `upgrade.bat` 會自動抓最新模板套用。模板只接管 `extraKnownMarketplaces` 與 `enabledPlugins` 兩個 key，不動客服的個人設定。

> **為什麼要用 CLI 主動裝 plugin。** `settings.json` 的 `enabledPlugins` 只是「宣告已啟用」，Claude Code 不會在開 session 時自動 clone/安裝外部來源的 plugin，得用 `claude plugin install` 主動裝。桌面 app 又不隨附 `claude` CLI，所以 FirstLogin 另外用 winget 裝 `Anthropic.ClaudeCode` 當 bootstrap 工具（跟 app 共用 `~\.claude`），裝完白名單四 plugin。

## 釋出流程（人工，全在 GitLab 上）

![打包發佈流程](img/02-release.png)

不用 CI、不用腳本，IT 在 GitLab 頁面手動建 Release：

1. 進本專案，左側 **Deploy → Releases → New release**。
2. Tag name 填新版號（如 `v1.0.0`），從 `main` 建立 tag。
3. 填標題與說明，按 Create release。

GitLab 會自動附上 Source code (zip) 並永久保存。客服固定從 Releases 頁下載最新版。要回收某一版，就指引客服改抓前一版。

## 安全注意事項

- 本 repo 與 GFF-Marketplace 的 `main` 都要設 protected branch、限縮 merge 權限。客服機器會執行來自這兩處的內容，等於誰能改 repo，誰就能在全部客服機器上跑碼。
- v1 沒用 managed-settings 硬鎖。白名單寫在客服可編輯的 `settings.json`，防君子不防小人。日後要硬鎖，在 `C:\Program Files\ClaudeCode\managed-settings.json` 放一份相同內容即可，不用重發安裝包。
- 安裝包 zip 不含任何祕密。憑證都在 FirstLogin 由客服本人輸入，存在他自己的環境變數與 Git Credential Manager。

## 關鍵設計決策

| 決策 | 選擇 | 理由 |
|---|---|---|
| 主介面 | Claude Desktop 的 Code 分頁 | GUI 對客服友善，設定與 plugin 跟 CLI 共用同一份 `~\.claude` |
| plugin 安裝 | FirstLogin 用 `claude` CLI 主動裝 | settings 只宣告不安裝外部 plugin；桌面 app 不帶 CLI，故另裝 Anthropic.ClaudeCode 當 bootstrap |
| 知識庫 | 魔鏡 memory MCP | 集中維護即時生效，避免本機檔案漂移 |
| GCP 憑證 | 每人 ADC 登入 | 本機零金鑰檔，IAM 只開 Logging Viewer |
| marketplace 憑證 | 個人 PAT（非 deploy token） | 不多一個共用祕密，可逐人撤銷，有稽核紀錄 |
| 軟體安裝分兩階段 | 全機共用放階段 1，per-user 放階段 2 | UAC 提權帳號可能不同，per-user 軟體與憑證要由客服本人 session 裝 |
| managed-settings | v1 不用 | 防君子不防小人可接受，日後補一份檔案即可硬鎖 |
| 客服端追蹤分支 | `main` | 更新已是手動，時機由通知控制就夠。若日後發現 app 會自動刷新 marketplace，再改開 cs-stable（分支名是 cs-config.json 參數） |
| Telegram | v1 不接 | 先把知識庫、log、GitLab 做穩 |
