## 技術文件編寫規範

為了確保新進成員能精確且無誤地閱讀與執行技術文件，請遵循以下規範：

### 1. 用詞一致性 (Terminology Consistency)
- **UI 術語優先**：文件中的名詞（如按鈕名稱、欄位標籤、狀態文字）必須與實際系統 UI 顯示的文字完全一致。
- **嚴禁使用同義詞**：避免為了修辭變化而切換同義詞（例如：嚴禁在同一流程中交替使用「餘額」與「點數」來描述同一資產）。優先確保技術精確性而非文學變化性。

### 3. 格式與標點符號 (Formatting & Punctuation)
- **清單項目不加句號**：檢查清單（Checklist）與條列式重點項目末端**不加句號**，以保持介面清爽並避免指令誤判。
- **段落描述加句號**：一般的完整敘述段落則維持正常標點符號。
- **UI 操作導向**：測試步驟應以使用者在介面上的動作為基準（點擊、輸入、觀察狀態變更）。
- **隱藏底層細節**：除非是專門的技術調試手冊，否則在面向新手的接入/測試文件中，應避免提及 SQL 查詢、Log 檔案名稱或內部代碼邏輯作為驗收標準。
- **操作 -> 預期結果**：每個測試步驟必須對應明確的 UI 可見結果。
