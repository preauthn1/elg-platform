# APIs

高併發博弈平台的後端。會員在代理底下註冊、用各種通道充值與取款、在三方遊戲商下注；平台依代理層級分潤。本檔是**詞彙表**，只定義這個領域的名詞是什麼，不寫它怎麼實作、也不寫決策理由——領域決策在 [`docs/knowledge/decisions/`](docs/knowledge/decisions/)，設計與計劃在 `docs/plans/`。

> 本檔是用詞的唯一權威。相關文件只講流程與操作，名詞一律以本檔為準：
> - 金流接入流程 — [`docs/金流接入流程/`](docs/金流接入流程/)
> - 遊戲接入流程 — [`docs/單一錢包遊戲接入流程/`](docs/單一錢包遊戲接入流程/)
> - 活動 V2 — [`docs/event-v2/`](docs/event-v2/)
> - 對帳資料表與時間欄位 — [`docs/對帳資料表與時間欄位.md`](docs/對帳資料表與時間欄位.md)
>
> **引用原文時照抄。** 介面上實際顯示的文字（後台按鈕、選單、狀態名，如「儲值/洗分審核」「已上分」）保留原樣；代碼裡的字面值（`valid_bet`、`vendors.percentage`、三方回調事件名）是識別字不是用詞。下面各條列出的英文，擋的是「拿它當中文行文裡的名詞用」，不是禁止寫出那個識別字。

## Language

### 會員與錢包

**會員**：
在某個代理底下註冊的帳號，可以充值、取款與下注。
_Avoid_: 用戶、user、玩家（指平台使用者時；遊戲語境的「玩家視角」「派給玩家」照用）

**玩家帳號**：
一個會員在某一家遊戲商那邊的帳號。我方對接多家遊戲商，同一個會員每家各有一組，彼此獨立；注單記的是玩家帳號，要對回會員必須先經過這一層。
_Avoid_: 三方帳號、遊戲帳號

**錢包**：
一個會員持有餘額的容器，依用途分種類。同一種錢包，一個會員只會有一個。

**多錢包**：
一個代理的設定，決定它底下的會員是否為每一種錢包種類各持有一個錢包。

**一般錢包**：
充值入帳、下注扣款、取款出帳都走的那個錢包。
_Avoid_: 主錢包、中央錢包、平台幣錢包

**活動錢包**：
只能用在活動上的錢包，不能直接提領。

**禮碼錢包**：
存放禮碼的錢包。

**禮碼**：
只能拿來下注、不能直接提領的籌碼，下注時會被優先消耗。「禮碼」與「泥碼」是公司內部並行的兩種叫法，兩者等價。
_Avoid_: 洗碼、打碼量（這兩個指的是下注量本身，不是籌碼）

**積分**：
活動的內部代幣：由活動發出、回到活動被消耗，人工調整只是補正。不是錢——不可提領、不抵注、無幣別。每次獲得成一批、各帶到期時間（可無限期）；扣除一律先扣最早到期的那批。代碼一律用 `score`。
_Avoid_: point／點數（本專案指錢包幣別的金額）、咬分（注單統計的 `total_score`，與積分無關）、多幣別積分（語意不成立）

**積分批次**：
一次發放產生的一批積分，各自有數量、剩餘數量與到期時間。會員的可用積分是所有未到期批次剩餘數量的加總。

**餘額**：
一個錢包當下可動用的金額。

**帳變流水**：
每一次餘額異動留下的憑證，記錄異動的原因與異動前後的金額。一次異動必定對應一列。
_Avoid_: 交易紀錄（指餘額異動的憑證時；轉帳錢包與遊戲商之間的「交易紀錄」是另一個東西）、ledger

### 幣別

**標準幣別**：
平台認得的幣別本身，法幣與虛擬貨幣都算，例如馬幣、美元、USDT、TON。同一種錢的千元寫法（`KVND`、`KIDR`）、付款方式（GCASH、PayMaya）、站台點數都不是幣別，不會出現在幣別主檔裡。
_Avoid_: 幣種、currency、單位變體

**錢包幣別**：
一個會員錢包用來計價的幣別。錢包建立的當下決定，之後不再改變。
_Avoid_: 會員幣別、帳本單位

**當前幣別**：
一個會員此刻選用的是哪一個幣別的錢包，決定他看得到什麼、能做什麼。多幣別開放後才有意義。

**可用幣別**：
一群代理可以開出哪幾種錢包幣別。
_Avoid_: 允許清單、白名單（指幣別清單時；IP 白名單是另一回事）、支援幣別

**預設幣別**：
可用幣別之中，新錢包會採用的那一種。

**通道幣別**：
會員在某條充值或取款通道上，實際支付或收取的幣別。與錢包幣別可以不同，兩者之間隔著入帳比例。充值側掛在支付通道上，取款側掛在取款銀行上，兩邊是同一個概念。
_Avoid_: 金流幣別、渠道幣別、銀行幣別

**通道覆蓋幣別**：
某個代理實際收得到、付得出的所有通道幣別。這是從通道設定推導出來的結果，不是誰填的欄位。

**商戶幣別**：
一個遊戲商戶用來記帳的幣別。同一家遊戲商底下的多個遊戲商戶可以各記不同幣別；玩家帳號本身不帶幣別，幣別在它所屬的遊戲商戶上。
_Avoid_: 遊戲商幣別、vendor 幣別

### 站點與代理

**站點**：
同一套系統對外經營的一個獨立品牌網站，各有自己的會員與代理。
_Avoid_: 站台

**代理**：
招攬會員、並從會員的投注中分潤的角色。代理之間構成上下線的層級。
_Avoid_: agent

**分潤**：
平台把會員投注產生的收益，依代理的層級與比例分配下去。
_Avoid_: 代理拆帳（「拆帳」單獨使用指平台與遊戲商之間的抽成，見「拆帳比例」）

**分潤比例**：
一個代理從它底下會員的輸贏中分得的比例。
_Avoid_: 分成百分比、百分比（指這個比例時）

**分潤金額**：
分潤比例套用到輸贏之後，代理實得的金額。
_Avoid_: 分成金額

**代理組別**：
把一群代理套用同一份設定的分組，依用途分成數種。一個代理在每一種用途上各屬於一個組別。
_Avoid_: 群組（指代理的分組時；「會員群組」是另一個東西）、agent group

**幣別組別**：
專門記載可用幣別與預設幣別的代理組別。

**支付組別**：
專門記載金流商戶與支付通道的代理組別。
_Avoid_: 財務組別、金流組別

### 充值、取款與金流

**充值**：
會員自己把錢交給平台、換成錢包裡可以下注的餘額。平台在這一側收款。
_Avoid_: 存款、儲值、Deposit

**取款**：
會員自己把錢包餘額換回錢、由平台付出。平台在這一側付款。
_Avoid_: 提款、提現、Withdrawal

**開分**：
代理或客服替自己、會員或下級代理加點數。和充值的差別在發起的人：會員自己付錢是充值，由代理或客服加點是開分。

**洗分**：
代理或客服替自己、會員或下級代理扣點數。是開分的反向，和取款的差別同樣在發起的人。

**拒絕洗分**：
會員不同意客服對他做的洗分，扣掉的點數退回錢包。只有設定成要會員同意的洗分才會發生，是會員的動作，不是審核結果。
_Avoid_: 玩家拒絕洗分

**被拒絕的洗分**：
扣了點數但最終沒有變成會員或代理拿到的錢的洗分：會員拒絕洗分，或所對應的取款訂單、洗分訂單最終被審核拒絕或退款。
_Avoid_: 被拒絕的提款、拒絕提款

**上分**：
充值訂單的款項確認後，點數真正加進錢包的那一步。訂單狀態「成功(未上分)」「已上分」講的就是它。
_Avoid_: 用「上分」指整件充值或開分（那兩件事各有正名）

**出款**：
平台把錢實際付給會員的動作，是取款的平台側視角。一筆取款可能經過多次出款嘗試，兩者不是一對一。

**代收**：
平台向會員收款的整套業務，涵蓋通道設定、下單與回調。
_Avoid_: 入金、收單

**代付**：
平台付款給會員的整套業務，涵蓋出款發起、銀行碼對映與回調。
_Avoid_: 出金

**充值訂單**：
會員發起一次充值時產生的單據。充值一定先有單，才有後續的付款與上分。
_Avoid_: 存款單、儲值訂單、充值單、訂單（單獨使用分不出是充值還是取款）

**取款訂單**：
會員發起一次取款時產生的單據。
_Avoid_: 提款單、提款訂單、取款單

**開分訂單**：
代理替自己開分時產生的單據，例如代理用銀行轉帳申請開分。審核通過後點數才加進代理自己的錢包。
_Avoid_: 代理充值訂單、代理支付訂單、代理自助上分訂單

**洗分訂單**：
代理替自己洗分時產生的單據，例如代理申請把自己錢包的點數出款到銀行帳戶。是開分訂單的反向。建單時點數就先從代理錢包扣除，審核拒絕或退回時才退還。
_Avoid_: 代理取款訂單、代理提款訂單、代理提款單

**撤單**：
撤銷一張還沒完成的充值訂單或取款訂單。這個詞屬於充值與取款，不用在注單上。

**金流商**：
提供代收或代付服務的第三方支付公司。
_Avoid_: 支付商、三方支付（單獨當名詞指那家公司時）、Cash Flow

**金流商戶**：
金流商發給平台的一組收付款身分，持有該身分的憑證、固定對應一種通道幣別。一個金流商戶底下通常掛著好幾條通道，代收與代付同時支援。它才是支付通道背後真正的身分——兩條通道即使名稱一字不差，只要商戶不同就是兩條。
_Avoid_: 通道商戶、代理商戶、渠道、商戶（單獨使用分不出是哪一側，改用「金流商戶」或「遊戲商戶」）、Agent Cash Flow、ACF、merchant

**支付通道**：
一個支付組別底下的一個付款選項，也就是會員在充值頁上看得到的一項。同一家金流商在同一個支付組別裡可以有好幾條，彼此的差別在背後綁的是不同的金流商戶。
_Avoid_: 代收渠道、支付方式、付款方式、渠道、金流設定、通道列、OrderType

**回調**：
金流商或遊戲商在交易有結果後主動打回平台的通知。平台不能預期它何時到，也不能假設它只到一次。
_Avoid_: 通知（指三方打回來的那個動作時；「大額通知」這類我方對內發出的通知不在此列）、notify、callback

**沙盒環境**：
金流商提供的測試環境，交易與金流都是假的。
_Avoid_: 測試環境（會與我方的測試站混淆）、Sandbox

### 手續費

**會員手續費**：
平台在存款或提款時向付款或收款的人收取的費用，由對方出錢，會讓他實際入帳或實收的金額變少。代理自己存提款時同樣適用。
_Avoid_: 稅、tax

**金流商手續費**：
平台為了一筆代收或代付付給金流商的費用，由平台出錢，不影響會員入帳或實收的金額。
_Avoid_: 支付商手續費（「支付商」不是正式名）、支付成本、payment cost

**成本費率**：
掛在金流商戶上的一個比例，代表平台付給金流商的手續費占交易金額多少。
_Avoid_: cost、成本比例

**網路費**：
加密貨幣在鏈上轉帳時付給區塊鏈網路的費用，收款方不是金流商，也不是平台。
_Avoid_: 礦工費、gas、網絡費

### 銀行

**標準銀行**：
平台認得的銀行本身，是各站點銀行資料的比對基準。
_Avoid_: 銀行主檔

**銀行別名**：
同一家標準銀行的其他寫法，用來讓三方回報的銀行名比對得到。
_Avoid_: alias

**代付銀行碼**：
代付時送給金流商的銀行代碼。同一家銀行在不同金流商可能是不同的碼。
_Avoid_: 三方銀行碼

### 遊戲商與注單

**遊戲商**：
提供遊戲給我方會員玩的第三方公司。
_Avoid_: 廠商、三方（單獨指那家公司時；「三方回調」「三方文件」這類複合詞照用）、vendor

**遊戲商戶**：
我方在某一家遊戲商那邊開的一組身分，持有該身分的憑證並固定對應一種商戶幣別。同一家遊戲商底下可以有多個遊戲商戶，玩家帳號隸屬於其中一個。
_Avoid_: 商戶（單獨使用會與金流商戶混淆）、vendor info

**遊戲商戶配置**：
一個遊戲商戶的對接參數，例如 API 位址與憑證。
_Avoid_: API 使用資訊

**無縫錢包**：
一種遊戲商對接方式。額度只有我方這一個錢包、完全由我方控管，玩家每次投注與派彩都由遊戲商即時回調過來異動餘額。
_Avoid_: 單錢包、單一錢包、Single Wallet、Seamless Wallet

**轉帳錢包**：
另一種遊戲商對接方式。玩家進遊戲前先把餘額轉進遊戲商的錢包，遊戲過程中由遊戲商控管額度，離開遊戲時再轉回我方。
_Avoid_: Transfer Wallet

**聚合商**：
把多家遊戲商包成同一套 API 轉給我方的中間商，例如 EliteHub、TitanHub、Top55SW、GMSW、target、PGSSW、DCT。EliteHub 是代碼中 TTHSW 的對外名稱，行文與介面一律寫 EliteHub。
_Avoid_: hub、TTHSW（指這家聚合商時；識別字照用）

**接入通道**：
一家遊戲商接到我方的路徑：經由哪一家聚合商，或不經聚合商。後台「廠商管理」欄位標題叫「通道」。
_Avoid_: 通道（單獨使用會與支付通道混淆）、渠道

**集成**：
經由聚合商接入的遊戲商；它的接入通道就是那家聚合商。
_Avoid_: 聚合（指遊戲商的接入方式時；注單統計的「聚合」照用）、aggregated

**直連**：
我方直接對接原廠、不經聚合商的遊戲商。
_Avoid_: 原廠、直接對接

**回調路徑**：
一家無縫錢包遊戲商向我方發回調時打的網址，由當站 apis 網域加上該遊戲商專屬的路徑後綴組成。轉帳錢包不適用。
_Avoid_: 回調網址、callback URL

**拆帳比例**：
平台與遊戲商之間分收益的比例。後台「遊戲商維護」表單上叫「拆帳比」，與代理分潤無關。

**注單**：
一次投注的完整紀錄，記著投注、有效投注、派彩與輸贏。

**投注**：
玩家在遊戲中下注，以及該次下注的金額。
_Avoid_: bet

**有效投注**：
一筆注單中計入統計與分潤的投注額，與投注額不一定相等。
_Avoid_: valid_bet

**有效投注比例**：
投注額要乘上多少才是有效投注。依「商戶×遊戲 → 遊戲 → 遊戲商」三層決定，取第一個有設定的；設為 0 代表該遊戲或該遊戲商整條線不計入流水。
_Avoid_: 轉換比例（指這個比例時；金流側的換算是「入帳比例」）

**派彩**：
遊戲結果產生後，平台付給玩家的金額。
_Avoid_: 中獎金額、結算（指付錢給玩家那個動作時；帳務上的「結算數字」「關帳」不在此列）、Settle

**輸贏**：
一筆注單結算後玩家的淨得失，以**玩家視角**計算——玩家贏為正、輸為負。
_Avoid_: win_lose

**彩金**：
累積獎池派發的獎金，與一般派彩分開計算。
_Avoid_: jackpot、頭獎

**活動獎金**：
因活動而發給玩家的獎金，與派彩、彩金都分開記。
_Avoid_: bonus、紅利（指我方活動發出的獎金時；三方回報欄位裡的「紅利」照抄原文）

**取消投注**：
遊戲商撤銷先前的投注，把扣掉的金額還給玩家。
_Avoid_: 撤單（那是充值訂單／取款訂單的動作）、cancel bet

**取消派彩**：
遊戲商撤銷先前的派彩，把已經發出去的金額收回。錢的流向與取消投注相反。
_Avoid_: unsettle

**退款**：
錢退回玩家或平台的通稱，語意依情境而定——可能指取消投注、取消派彩，也可能指轉帳到遊戲商失敗後退回。寫文件時改用精確的那一個。
_Avoid_: 回滾、Rollback、Refund

**SunCity**：
iGaming 平台的 Clubsuncity 品牌，VW2 站用的轉帳錢包遊戲商，程式識別名 `Suncity`（vendor 292），與 Play8oy（同平台）共用同一份 API 規格。
_Avoid_: Clubsuncity（三方品牌名，只在 deep-link scheme 出現）、hero9（那是 VW2 站的品牌不是遊戲商）

### 活動

**活動**：
在一段期間內，依會員的投注或充值等行為發放獎勵的機制。

**流水**：
會員要累計達到的投注量門檻，達到了才能把活動獎金領走或取款。與「洗碼」「打碼量」講的是同一種量，但流水特指帶著門檻與達成度的那個。

**鎖分模式**：
會員參與活動期間，錢包之間的餘額轉移受到限制的狀態。

**紅包**：
一種活動：會員花積分抽一次，得到一筆隨機金額的活動獎金。積分在這裡是門票不是獎品；獎金照其他活動的規則走（直接入主錢包，或先進活動錢包打流水）。
_Avoid_: angpow（指這個活動時；`AngpowService` 是識別字照用）、紅包雨（那是前台動畫）

**會員週期**（後台欄位名「可重複參加」，DB `member_period`）：
單一活動自己設定的日／週／月／年區間，管「同一個會員多久能再抽」。每人的領取次數與金額在這個區間內累計；不勾「參加即領獎」的參加紀錄，區間一過就作廢。目前只有紅包用；其他活動的週期由活動類型決定。
_Avoid_: 活動週期（2026-09-30 前的舊名，當時以為只有一個週期）

**全站週期**（後台欄位名「包括期間」，DB `total_period`）：
單一活動自己設定的日／週／月／年區間，管「全站的池子多久重新開一池」：全站總次數與總金額在這個區間內累計，過了重新計。只管統計、不作廢。與會員週期各自獨立：「每日可抽 1 次、每週全站 50 次」＝會員週期每日＋全站週期每週。目前只有紅包用。

### 對帳

**BR**：
單一遊戲商回報進來、未經轉換的注單，每家的欄位名與口徑都不同。
_Avoid_: 原始注單、bet record

**TBR**：
把各家 BR 轉成同一組欄位之後的注單。跨遊戲商查注單看這裡，不必逐家去湊。
_Avoid_: 總注單、統一注單

**SBR**：
把 TBR 依「每人每小時每款遊戲」聚合後的結算數字，報表與代理分潤讀它。
_Avoid_: 小時彙總

**小時桶**：
SBR 的聚合單位，以整點為界。
_Avoid_: hour bucket

**關帳**：
SBR 寫入方式的分水嶺，界線是當日台北時間 00:00。還沒關帳的時段可以整段重算，已經關帳的只能追加差額。

**重算**：
還沒關帳的時段重新產生 SBR，直接覆蓋原本的數字。

**調帳**：
已經關帳的時段發現數字不對時，追加一列差額，原本的數字不動。

**調帳差額**：
調帳追加的那一列。它記的是差額不是總額，把它跟原本的列加總才是正確數字。
_Avoid_: correction

**對帳**：
「對齊驗證」與「補帳作業」的合稱。指涉不清時要講明是哪一個。
_Avoid_: 修帳、補單（這兩個在客服與維運語境指人工調整會員餘額，是另一件事）

**對齊驗證**：
比對 BR、TBR、SBR 三者的數字是否一致，只讀不寫。

**補帳作業**：
把對不上的數字補正的寫入作業。

### 金額換算

**匯率**：
1 單位甲幣別等於多少乙幣別。市場事實，與平台的收費無關。

**買賣價差**：
同一個幣別對，代收與代付採用不同的比例，差額歸平台。
_Avoid_: spread

**通路係數**：
特定通路的折讓或加成，與幣別無關。

**入帳比例**：
通道幣別的金額要乘上多少，才是錢包幣別的點數。方向固定為「1 單位**通道幣別**換得多少**錢包幣別**」——充值是會員支付的金額、取款是會員收取的金額，兩側同向。它是匯率、買賣價差、通路係數相乘之後的結果，因此**不等於匯率**。
_Avoid_: rate、匯率（指這個換算結果時；純粹的市場匯率就叫「匯率」）、轉換比例

**單位倍率**：
同一種幣別的不同計價單位之間的縮放，例如遊戲商以千元報價、平台以元記帳。發生在遊戲商那一側，由商戶設定上的比例吸收。與匯率無關。

**顯示單位**：
一群代理的某個可用幣別，要用元還是千元呈現給玩家與後台報表。只影響畫面上的數字，帳本與 API 的金額永遠是元。
_Avoid_: 千分制幣別、KVND 錢包

### 文件與知識

**知識庫**：
repo `docs/knowledge/` 底下、以 Open Knowledge Format 書寫的那一套文件，是系統行為的唯一正本；給 RD、PM 與 agent 讀。
_Avoid_: 文件庫、git wiki、OKF（指這套文件時；OKF 是格式名）

**客服 wiki**：
Outline 上的文件，只放客服看的操作手冊與客服詞彙；引用系統規則時指向知識庫，不自己重寫一份。
_Avoid_: wiki（單獨使用時）、Outline（指這套文件時；Outline 是工具名）

**知識文件**：
知識庫裡的一份 OKF 文件，分六種類型：架構、API、命令、規則、資料表、決策。
_Avoid_: 功能頁、功能說明（指單一份時）、規格頁

**文件 ID**：
知識文件的識別碼，寫法是 `<區>/<slug>`，例如 rules/withdrawal-member-fee；程式與測試的標記靠它找到文件。
_Avoid_: 功能短編號、頁鍵、功能代碼

**規則 ID**：
規則表裡一條規則的識別碼，寫法是 `<文件 ID>#R-n`，例如 rules/withdrawal-member-fee#R-3。
_Avoid_: SSOT-n（指這個編號時）

**原子知識**：
能獨立理解、引用、更新的一份知識文件或一條規則。
_Avoid_: 知識點、知識片段

**SSOT**：
知識文件規則表裡的一條事實：在什麼情況下、做什麼操作，系統會怎麼表現；文件內連號為 R-n，規則 ID 是「文件 ID#R-n」。寫進去的代表 RD 與 PM 都認定系統應該這樣。
_Avoid_: 規格、需求（指這一條事實時）、驗收條件

**驗收**：
證明某一條 SSOT 成立的證據，只認 feature test；QA 的人工驗證不算驗收、不進知識庫。SSOT 是事實，驗收是證明。
_Avoid_: 測試（指證據這個角色時）、驗證、人工驗收

## Relationships

- 一個**站點**有自己的**會員**與**代理**；多數站點各有一套資料庫
- 一個**代理**招攬多個**會員**，代理之間構成上下線層級
- 一個**代理**在每一種用途上各屬於一個**代理組別**（**幣別組別**、**支付組別**各一）
- 一個**會員**在每一家**遊戲商**各有一組**玩家帳號**
- 一個**玩家帳號**隸屬於一個**遊戲商戶**；**商戶幣別**掛在遊戲商戶上，不在玩家帳號上
- 一個**金流商**發給平台多個**金流商戶**，一個金流商戶固定對應一種**通道幣別**
- 一個**金流商戶**底下掛多條**支付通道**，代收與代付同時支援
- **BR** 轉成 **TBR**，**TBR** 依每人每小時每款遊戲聚合成 **SBR**
- **分潤比例**套用到**輸贏**得出**分潤金額**
- **入帳比例**＝**匯率**×**買賣價差**×**通路係數**
- 一筆費用算**會員手續費**還是**金流商手續費**，只看誰出錢：付款或收款的人出的是前者，平台出的是後者
- **會員手續費**與**金流商手續費**互不影響：前者改變會員入帳或實收的金額，後者只記在平台的帳上
- **成本費率**掛在**金流商戶**上，每個金流商戶各自一個
- **網路費**由會員還是平台負擔，由**金流商戶**的設定決定，不是固定的
- **被拒絕的洗分**仍計入總開分與總洗分，但不計會員手續費與實際金額；報表上的洗分列也包含會員自己發起的**取款**，所以取款訂單最終被拒絕或退款的那一列同樣算被拒絕的洗分
- **知識庫**是 **SSOT** 的唯一正本；**客服 wiki** 只引用知識庫，不另寫一份規則
- 一份**知識文件**以一個**文件 ID** 識別；規則類的知識文件內有多條 **SSOT**，每條以一個**規則 ID** 識別；一條 SSOT 可以有多筆**驗收**
- feature test 以**規則 ID** 綁到它證明的那一條 **SSOT**；unit test 不綁、不算驗收

## Flagged ambiguities

- **「站點」與「白標」**：兩者日常交替使用。多數情況下一個站點就是一個白標，但 VWorld 是例外——它底下有數個站點共用同一套資料庫。本檔以**站點**為正式名；「白標」在指涉貼牌經營這個商業模式時仍可使用。**尚未釐清**：需不需要把兩者拆成兩個詞條。
- **「通道商戶」**：2026-09 編寫本檔時造的詞，codebase 從未使用，且方向相反——通道隸屬於商戶，不是商戶隸屬於通道。已解決：正式名為**金流商戶**。
- **「流水」**：同時指「餘額異動的憑證」與「活動的投注量門檻」。已解決：前者是**帳變流水**，後者是**流水**；單獨寫「流水」時務必確認指的是哪一個。
- **「組織幣別」**：系統裡確實有這個欄位，但用途已不明確——它不是新會員錢包幣別的來源（那是**預設幣別**），目前確認會影響的只有註冊驗證邏輯。**尚未釐清**：要用它之前先確認當下的讀取端在做什麼，釐清後再決定收不收進詞彙表。
- **「通道」**：同時指金流側的**支付通道**與遊戲商側的**接入通道**。已解決：單獨寫「通道」一律指支付通道；遊戲商側寫**接入通道**，只有介面欄位標題照抄為「通道」。
- **「手續費」**：單獨使用時同時指「向會員收的」與「付給金流商的」，後台報表又把前者標成「手續費」、後者標成「支付商手續費」。已解決：前者是**會員手續費**，後者是**金流商手續費**，行文一律寫全名；引用後台欄位名時照抄原文。
- **「費率」**：單獨使用時分不出是**成本費率**（平台付給金流商的比例）還是會員手續費的百分比。已解決：前者寫**成本費率**，後者寫「會員手續費的百分比」。
- **「單一錢包」與「無縫錢包」**：repo 現行大量使用「單一錢包」（含目錄名與 skill 文件）。已解決：正式名為**無縫錢包**（seamless wallet 的業界標準譯法），既有用語逐步收斂。
- **「被拒絕的提款」**：工單用它指 SR02N 報表上不該算手續費與實際金額的洗分，字面像「取款訂單被審核拒絕」，但工單實例全是會員**拒絕洗分**、沒有取款訂單。已解決：正式名為**被拒絕的洗分**，同時涵蓋拒絕洗分與取款訂單、洗分訂單最終被拒絕或退款；「提款」不是正名。
- **「wiki」**：單獨使用時同時指 Outline 與 git 裡的文件。已解決：git 那一套是**知識庫**，Outline 那一套是**客服 wiki**；兩者讀者不同，單獨寫「wiki」時務必確認指的是哪一個。
- **「功能說明」**：同時指 Outline 的「功能說明」collection 與其中的單一頁。已解決：git 裡的單一份是**知識文件**；Outline 的單一頁與 collection 名稱引用時照抄原文。
