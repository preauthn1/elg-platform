# docs/plans

設計文件與實作計劃的存放地，依「`YYYY-MM-DD-主題`」目錄組織（日期＝主題起始日）。

## 規則

- **只放進行中的主題**。設計與計劃文件只在「進行中」期間存在，落實後刪除、不歸檔。本目錄的體積等於進行中的工作量。
- **刪除前先搬遷**：規則與「為什麼不這樣做」寫進對應 class 的 docblock；決策當下的取捨寫進 MR 描述與 commit 內文。
- **沒有狀態索引**。要知道有哪些主題在進行，看目錄清單；要知道某主題做到哪，看 git log 與對應代碼，不看任何文件裡的狀態欄。
- **考古用 git**：已刪除的主題以 `git log --all --oneline -- docs/plans/<目錄名>/` 找回設計文件的歷史版本。

## 為什麼不維護索引

2026-09-14 盤點 15 個主題，全部與代碼脫節，且文件建立後沒有一份在代碼變更後被同步過；索引層的狀態欄至少 3 個主題與 master 相反、兩三個月無人發現。沒人維護的狀態欄是另一個假來源，所以整層退場。
