## 1. 構想

`standard_banks` 升級為中台 canonical 主檔，push mirror 至 agent / member / vendor 各專案 DB，讓所有專案共用同一銀行身份。[方案 C / D](./方案D-完整四層收斂.md) 的 schema 設計已為此預留（`standard_banks` 全域唯一、無白標維度）。

## 2. 為什麼不能跳過 C（A＋B＋E 不可行）

E 的價值主張是「所有專案共用同一銀行身份」，前提是被推送的 `standard_banks` 完整、乾淨、可信——這正是 C-core（C1–C5）建立的：

- **canonical 完整性**：方案 B 做完時 canonical 只覆蓋營運幣別；
- **同碼異義解析**：未解的 `MYR0035` 類衝突會被同步到其他專案，跨專案放大為資損級錯誤；
- **對映率**：回填不足時 mirror 出去的是殘缺映射。

此時推中台等於**把混亂同步到其他專案**。最短路徑：**A → B → C → E**（C-tail 在等中台基建期間補齊，屆時與方案 D 殊途同歸）。

## 3. 現況與結論

中台基礎設施尚未規劃，工時無法估。本次分級決策**不納入 E**，僅列為 C/D 完成後的遠期方向。
