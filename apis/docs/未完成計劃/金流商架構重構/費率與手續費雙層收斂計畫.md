# 費率與手續費雙層收斂計畫（cost ＋ tax）

> **軌道**：金流商架構重構・軌道②。文件地圖見 [./README.md](./README.md)、狀態與決策見 [RB/TODO.md §3.1](../RB/TODO.md)。
> **目標**：把「平台成本 `cost`」與「使用者手續費 `tax`」兩個欄位家族都從 `agent_cash_flows`（ACF）層收斂到 `agent_cash_flow_order_types`（ACFOT）層，消除雙層存放；tax 另把計算時機從創單改為 callback 成功時。
> **狀態**：草稿（tax 部分待 PO 決議；cost 部分待排期）
> **決策主體**：PO（tax 語意）／PM（排期）

---

## 1. 共同問題：ACF / ACFOT 雙層冗餘

兩個語意不同的欄位家族面臨**同一個結構問題**——同時存在於兩張表、代碼擇一讀取、後台兩層皆可編輯但操作者無從得知哪層生效：

| 欄位家族 | 語意 | ACF 層 | ACFOT 層 | 現行讀取 |
|---|---|---|---|---|
| `cost` / `cost_type` | 平台成本（渠道費率） | `agent_cash_flows.cost` | `cost`, `cost_type`（欄位已加，migration 完成） | 讀 ACF |
| `tax` / `tax_percentage` | 使用者手續費 | `agent_cash_flows.tax`, `tax_percentage`（**decimal(11,5)**，migration `2026_04_16_000001`） | 同名欄位（decimal(18,4) / decimal(8,4)） | **因 provider 而異**：TngPin 讀 ACFOT、其他全讀 ACF |

ACFOT 既能按 `(agent_cash_flow_id, order_type_id)` 配置，就已涵蓋 ACF 層所有可表達的場景（ACF 固定費可平攤到旗下所有 ACFOT，數學上等價）——**ACF 那層沒有不可被 ACFOT 表達的東西**，收斂方向一致：**ACFOT 為唯一來源，ACF 層欄位標 deprecated 後移除**。

## Part I — tax（使用者手續費）

### 2. 代碼證據

**創單路徑（所有 provider）** `app/Services/OrderService.php:76-78`：

```php
$point = Common::numMul($amount, (string) ($agentCashFlow->rate ?? 1), 4);
$percentage = Common::numMul($point, (string) ($agentCashFlow->tax_percentage ?? 0), 4);
$tax = Common::numAdd((string) ($agentCashFlow->tax ?? 0), $percentage, 4);
```

`tax = ACF.tax + amount × rate × ACF.tax_percentage` → 寫入 `orders.tax`。**完全不讀 ACFOT。**

**TngPin callback 路徑** `app/Services/Payment/Providers/TngPin/DepositCallback.php:161-181`：`tax = ACFOT.tax + amount × rate × ACFOT.tax_percentage` → **覆寫** `orders.tax`。**完全不讀 ACF。**

**其他 provider callback** `app/Services/Payment/Traits/DepositCallbackTrait.php:153-154`：`calculateDepositTax()` 整段被註解，註解明示「callback 不再覆寫」——固化了「ACF 為唯一 source」的錯誤假設，方向選錯（正確方向是「創單不算、callback 才算」，與 TngPin 現行模式一致）。

### 3. 實證數據（TPower 2026-05-22）

| 指標 | 數值 |
|---|---|
| ACF 總數 | 約 500+ |
| ACF 有 tax 設定的筆數 | **2**（acf_id 151, 305；使用率接近 0%） |
| ACFOT 有 tax 設定的筆數 | 11（跨 acf_id 151, 213, 215, 305）——**實際生效的稅源** |

acf_id 151 同時有 ACF.tax_percentage=0.075 與 ACFOT.tax_percentage=0.075：若改「加總」設計，TngPin 訂單會變收 15%，現行只收 7.5%（走 ACFOT）——證明「加總」假設與現實不符。

### 4. 現行設計缺陷

1. **雙層存放是純粹冗餘**（見 §1）。
2. **創單時就算 tax 違反「資料反映事實」**：失敗訂單也寫入 tax → 報表污染（`SUM(orders.tax)` 含失敗單預估值）、客服誤導、欄位語意不自洽。`orders.tax` 應是「實際收到的手續費」。
3. **雙標準路徑 UX 陷阱**：後台改 ACF.tax 對 TngPin 無效；改 ACFOT 對其他 provider 無效。無任何 guard 或 UI 提示。

### 5. 目標設計

| 項 | 設計 |
|---|---|
| 唯一來源 | ACFOT；`agent_cash_flows.tax` / `tax_percentage` 標 deprecated，下一個 major release 移除 |
| 創單時 | `orders.tax = 0`（或 NULL），不從任何表預算 |
| 前端預估 | UI / API 即時從 ACFOT 算 expected_tax，read-only 不寫 DB |
| callback 成功 | 從 ACFOT 算實際 tax 寫入 `orders.tax`（把 TngPin 的計算抽到 `DepositCallbackTrait` 統一入口，推廣到所有 provider） |
| callback 失敗 | `orders.tax` 維持 0 / NULL |
| 公式（不變） | `tax = ACFOT.tax + amount × rate × ACFOT.tax_percentage`，`rate` 仍從 ACF 取（ACF 其他欄位不在本計畫廢棄範圍） |

> **⚠️ 實作陷阱（2026-07-06 讀碼）**：`DepositCallbackTrait.php:239-270` 有一段**已被完整註解**的舊 `calculateDepositTax()`，它讀 ACFOT 但公式是 `amount × tax_percentage`（**漏乘 `rate`**），與上表正確公式在 `rate≠1` 時結果不同。Phase 2 應**寫新方法**而非解除註解重用，並在命名／測試中標明與舊方法的公式差異，避免日後誤認重複。

## Part II — cost（平台成本）

### 6. 問題與方案

`agent_cash_flow.cost` 為代理層級欄位；若僅為了調整渠道費率，必須為每個代理建立獨立商戶配置，維護成本極高。

- ACFOT 已加 `cost` / `cost_type`（1=百分比 2=固定金額）欄位（migration `2026_03_16_000001` 完成 ✅）。
- **⚠️ 校正（2026-07-06 讀碼）**：ACFOT.cost / cost_type **目前全 codebase 無任何 Service 讀取做費率運算**（僅 patch 命令的顯示表格接觸，且讀的是 channel.cost）——屬「schema 先行、代碼未接」。提案標「migration 完成 ✅」正確，但「完成」不等於生效；切換的具體 Service 檔案必須指名（見下）才算真正落地，否則此欄會長期空置。
- 費率讀取切換至 ACFOT 後，`agent_cash_flow.cost` 標 deprecated；migration comment 已明示「待份桶 & SR99 切換後移除」（`agent_cash_flow.cost` 仍有讀取端 `AgentCashFlowListService.php:126`，勿搶跑）。
- **⚠️ 影響範圍**：**份桶**、**SR99** 讀取費率的邏輯須同步切換至新欄位，列為獨立子任務——**動工前先 grep 出對應 Service 並在 Phase 2 checklist 指名**（目前只寫「列為獨立子任務」，缺具體檔名易遺忘）。

## 7. 遷移策略（tax 與 cost 時程對齊）

### Phase 1：對齊資料（無代碼變更）

1. 跨白標掃描所有 `ACF.tax > 0 OR ACF.tax_percentage > 0` 的設定；
2. 若旗下 ACFOT 已有自己的 tax 設定 → **保留 ACFOT 值**；沒有 → 將 ACF 值複製到 ACFOT；
3. 對齊後跑 `order:check-deposit-tax-applied` audit，確認所有 tax > 0 訂單能歸類到 ACFOT 來源；
4. cost 比照辦理（ACF.cost → 旗下 ACFOT.cost）。

### Phase 2：代碼切換

- [ ] `OrderService::createOrder` 移除 tax 計算，`orders.tax` 預設 0
- [ ] `DepositCallbackTrait` 新增 `calculateDepositTaxFromAcfot()`，所有 provider callback 成功路徑呼叫
- [ ] TngPin DepositCallback 改用 trait 統一方法（保留現有實作直到新 trait 測試覆蓋穩定）
- [ ] 測試覆蓋（含失敗 callback 不寫 tax 的 case）
- [ ] **P3-L6** 份桶費率讀取切換至 `ACFOT.cost / cost_type`
- [ ] **P3-L7** SR99 費率讀取切換至 `ACFOT.cost / cost_type`

### Phase 3：UI / 後台

- [ ] ACF 編輯介面：`tax / tax_percentage / cost` 標 deprecated 或移除編輯入口
- [ ] ACFOT 編輯介面：補上稅率／費率設定區塊
- [ ] 前端 / API 預估手續費端點改讀 ACFOT

### Phase 4：清理

- [ ] 歷史 audit 確認所有新訂單 tax 來源都是 ACFOT
- [ ] 觀察一個會計週期後，下一個 major release ALTER DROP ACF 層欄位

## 8. 風險

| 風險 | 緩解 |
|---|---|
| 歷史 orders.tax 報表口徑變動（失敗單 tax 從非 0 變 0） | 切換前後跑 30 天對照表；報表改加 `WHERE status=1` |
| Phase 1 資料對齊出錯 → 收費金額變動 | 對齊腳本 dry-run＋逐白標驗證＋diff 報告審閱 |
| ACFOT 缺對應 row → tax 變 0 | Phase 1 前先檢查 ACFOT 覆蓋率補齊 |
| TngPin regression（唯一已走 ACFOT 的 provider） | 保留現有實作直到新 trait 穩定 |

## 9. 偵測工具

`php artisan order:check-deposit-tax-applied [--date=]`（`app/Console/Commands/Order/CheckDepositTaxApplied.php`）：對 tax > 0 的已付款訂單比對 expected_acf / expected_acfot，歸類 **ACF / ACFOT / UNKNOWN**。Phase 1 完成後應全部歸類 ACFOT。
