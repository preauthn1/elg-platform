# 三、測試與提交驗收

> ← [遊戲商接入完整操作流程 (單一錢包)](index.md)

本章節說明開發完成後的測試流程。請確保你已在 **DEV 環境** 配置完成，且程式碼已部署至對應分支。

---

## 測試場景：會員端 (Seamless Wallet)

這是單一錢包最核心的測試路徑，驗證玩家在遊戲中產生的所有動作是否能正確異動平台餘額。

### 1. 進入遊戲驗證
*   **目標**：驗證玩家能正常透過 API 取得遊戲網址並進入遊戲。
*   **操作步驟**：
    1.  **發起進入遊戲**：由前台點擊該遊戲圖示。
    2.  **跳轉驗證**：驗證是否能成功跳轉至遊戲頁面，且玩家帳號已正確登入。
    3.  **餘額顯示**：檢查遊戲介面顯示的餘額是否與平台帳戶餘額一致。

### 2. 投注 (Bet) 測試
*   **目標**：驗證下注時平台餘額能即時扣除。
*   **操作步驟**：
    1.  **執行下注**：在遊戲中進行一筆投注。
    2.  **平台檢查**：查看平台會員帳號，確認餘額已正確扣除對應金額。
    3.  **注單檢查**：於後台檢查是否產生對應的遊戲注單紀錄。

### 3. 結算 (Settle) 測試
*   **目標**：驗證派彩時平台餘額能即時增加。
*   **操作步驟**：
    1.  **達成中獎**：在遊戲中達成中獎結果。
    2.  **平台檢查**：確認平台會員餘額已增加中獎金額。
    3.  **狀態檢查**：確認注單狀態已更新為已結算。

### 4. 退款 (Refund/Rollback) 測試
*   **目標**：驗證遊戲異常或取消時，餘額能正確回滾。
*   **操作步驟**：
    1.  **觸發取消**：（通常需配合遊戲商沙盒工具）觸發一筆取消投注的請求。
    2.  **結果確認**：確認平台餘額已返還原下注金額，且注單狀態顯示為已退款。

---

## 章節檢查清單

- [ ] **進入遊戲**：可正常取得遊戲 URL 並在遊戲中看到正確餘額
- [ ] **投注回調**：接收 `bet` 請求後，平台餘額正確扣除且紀錄注單
- [ ] **派彩回調**：接收 `settle` 請求後，平台餘額正確增加且更新注單
- [ ] **退款回調**：接收 `refund` 請求後，平台餘額正確還原
- [ ] **冪等性驗證**：重複發送相同 transactionId 的請求，平台應回傳成功且不重複扣/增金額
- [ ] **資格檢查**：當會員被鎖定或商戶維護時，`bet` 回調應正確拒絕請求
