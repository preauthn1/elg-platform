# 對帳資料表與時間欄位

> **名詞定義不在這裡**——BR／TBR／SBR、關帳、重算、調帳、調帳差額、對齊驗證、補帳作業等，見 [`GLOSSARY.md`](../GLOSSARY.md) 的「對帳」章節。本檔只記它們**對應到哪些資料表、哪些報表代號，以及時間欄位的語意與時區**。
> **本檔也不教操作**——對帳 SOP（補帳作業、SBR 調帳／重算、recovery_logs 審計）由 `reconcile-bet-records` skill 維護；查調帳差額的列由 `list-sbr-corrections` skill 維護。

## 三表對應的資料表

| 名詞 | 對應資料表 |
|---|---|
| **BR** | `{tname}_bet_records`（每家遊戲商各一張） |
| **TBR** | `total_bet_records` |
| **SBR** | `summary_bet_records` |

## 周邊資料表與報表代號

| 名稱 | 說明 |
|---|---|
| `{tname}_deal_records` | 部分無縫錢包遊戲商的**細粒度事件流**（bet / gameRoundResult / refund 等沖銷事件） |
| `bet_record_recovery_logs` | BR / TBR 修正的**審計表** |
| `summary_bet_records.correction = 1` | 詞彙表的「**調帳差額**」就是這種列 |
| **SR11** | 「代理商遊戲平台對帳表」報表代號，後端讀 `summary_bet_records`（以 `summary_time` 切日） |
| **SR12** | 「遊戲投注記錄」報表代號，後端讀 `total_bet_records` |
| **SR14** | 「現金紀錄表」報表代號（語意：會員餘額變化全紀錄；⚠️ APIs 倉暫無實作） |

## 關帳的實際界線

詞彙表寫的「當日台北時間 00:00」，換算後是**前一日 UTC 16:00**——三表時間欄位一律以 UTC 儲存（見下節），比對時用的是這個值。

## 三個時間欄位

| 欄位 | 出現於 | 語意 |
|---|---|---|
| `bet_time` | BR、TBR | 注單**下注時間**（部分遊戲商以此欄做 SBR 分桶，見下） |
| `payout_time` | BR、TBR | 注單**結算時間** |
| `data_time` | SBR | 小時桶的**桶起點時間** |
| `summary_time` | SBR | SBR 列**寫入時間** |

> **三表時間欄位一律以 UTC 儲存。** 依據：`config/app.php` 的 `timezone=UTC`、`TotalBetRecord` 的 `@property payout_time(UTC)`、多份 migration 註解明寫 `(UTC)`，以及 SBR 命令內部把輸入的 UTC+8 轉成 UTC 再查詢。
>
> ⚠️ **目前沒有任何遊戲商被證實在寫入路徑上顯式改時區**（查到的都是送單時戳或簽名時戳，不是寫入路徑）。遇到某家疑似不是 UTC 時，先查該遊戲商對接卡的「時區」段確認，不要預設它沒有、也不要預設它有。
>
> ⚠️ **時區差異真正會發生的位置有兩處**：①遊戲商的外部介面／後台／匯出檔顯示時區各異（多為 GMT+8 或 SGT、少數 UTC），人工核對時要自己換算；②該遊戲商在 `config/summary_bet_record.php` 的 `time_field` 設定——選 `bet_time` 還是 `payout_time` 當 SBR 的分桶依據，**選錯欄位會補到錯的時段**。
