# 三、測試與提交驗收

> ← [金流商接入完整操作流程](index.md)

本章節說明開發完成後的測試流程。請確保你已在 **DEV 環境** 配置完成，且程式碼已部署至對應分支。

---

## 測試場景一：會員端 (Frontend)

這是最常見的測試路徑，模擬真實玩家進行儲值與提款。

### 1. 代收 (Deposit) 測試
*   **目標**：驗證玩家能正常跳轉至金流商支付頁，且回調後點數能自動入帳
*   **操作步驟**：
    1.  **發起代收**：登入前台 > 錢包 > 儲值
    2.  **選擇渠道**：選取正確的幣別與剛接入的金流商/渠道
    3.  **跳轉驗證**：填入金額並點擊確認，驗證是否能成功跳轉至金流商收銀台或顯示支付 QR Code
    4.  **三方確認**：前往金流商後台，確認是否有產生對應的待支付訂單
    5.  **模擬回調**：
        - 於代理後台 > **下線會員管理** > **支付訂單管理** 找到該訂單
        - 向金流商客服請求發送測試回調（或使用自備腳本模擬通知）
    6.  **結果確認**：
        - **訂單狀態**：應更新為「已上分」
        - **會員點數**：應正確增加

### 2. 代付 (Withdrawal) 測試
*   **目標**：驗證系統能正常向金流商發起打款請求，且回調後訂單狀態正確變更
*   **操作步驟**：
    1.  **發起代付**：登入前台 > 錢包 > 洗分
    2.  **填寫資訊**：填入銀行資訊與金額，確認送出
    3.  **審核發起**：
        - 登入代理後台 > **自助洗分** > **洗分訂單審核**
        - 找到該筆訂單，點擊「**代付付款**」
    4.  **三方確認**：前往金流商後台，確認是否有收到這筆打款請求
    5.  **模擬回調**：請求金流商發送代付成功回調
    6.  **結果確認**：
        - **訂單狀態**：應更新為「已付款」
        - **會員點數**：應正確扣除

## 測試場景二：代理端自助 (Agent Self-service)

針對代理自身需要對其商戶號進行代收或代付的場景。

### 1. 代收 (Deposit) 測試
*   **目標**：驗證代理能為自己的商戶號進行代收，且資金能正確進入代理餘額
*   **操作步驟**：
    1.  **發起代收**：登入代理後台 > **代理自助開洗分** > **開分申請-快速充值**
    2.  **選擇渠道**：選取幣別後，驗證新接入的金流商與其渠道是否出現在清單中
    3.  **跳轉驗證**：填入金額並確認，驗證是否能正常跳轉至支付頁面或收銀台
    4.  **三方確認**：
        - 至代理後台 > **自助上分** > **代理支付訂單管理** 找到該筆訂單
        - 登入金流商後台，核對是否有產生對應的待支付訂單與正確金額
    5.  **模擬回調**： 請求金流商模擬回調（或是手動觸發測試回調）
    6.  **結果確認**：
        - **訂單狀態**：應更新為「已上分」
        - **代理餘額**：應正確增加。

### 2. 代付 (Withdrawal) 測試
*   **目標**：驗證代理能將餘額提領出款，且系統能正確串接金流商代付 API
*   **操作步驟**：
    1.  **發起代付**：登入代理後台 > **代理自助開洗分** > **洗分申請**（銀行轉帳方式）
    2.  **填寫資訊**：確認可選擇該金流商支援的銀行，填寫資訊後送出
    3.  **審核發起**：
        - 至代理後台 > **代理自助開洗分** > **代理洗分訂單審核** 找到該訂單
        - 點擊「**代付付款**」按鈕，此時系統會正式呼叫金流商 API
    4.  **三方確認**：登入金流商後台，核對是否有產生對應的打款單號與正確金額
    5.  **模擬回調**：等待或請求金流商發送代付結果回調
    6.  **結果確認**：
        - **訂單狀態**：應更新為「已付款」
        - **代理餘額**：應正確扣除

- [ ] **代收**：可以正常跳轉支付頁面，模擬回調後訂單狀態更新為「已上分」
- [ ] **代付**：代付請求成功送出，模擬回調後訂單狀態更新為「已付款」
- [ ] **後台管理**：對應的訂單管理介面（支付訂單、儲值/洗分審核）能查看到交易
- [ ] **回調響應**：回傳給金流商的字串（如 `OK` 或 `success`）符合 API 規範
