### 🔧 通用 Trait 說明

**DriverTrait.php**

- 提供 `getDriverName()` 方法
- 用於獲取金流商名稱（用於日誌、錯誤訊息等）

**WithdrawalPayoutTrait.php** - 代付業務通用邏輯

- `getWithdrawalOrder()` - 獲取並驗證提款訂單（含狀態檢查）
- `validatePayoutOrder()` - 驗證已查詢的提款訂單是否可發起代付（不重新查 DB；`Withdrawal::handle()` 必須於開頭呼叫）
- `checkWithdrawalOrderStatus()` - 檢查訂單是否允許接收回調：只放行 21、22，其餘狀態（含 29）拒絕並告警
- `createPayoutRecord()` - 建立代付請求紀錄
- `convertPayoutBankCode()` - 透過 `info[available_banks]` 轉換我方銀行代碼為三方代碼
- `handlePayoutRequestException()` - 處理 HTTP 請求異常（建立失敗紀錄 + 日誌 + 回失敗響應）
- `handlePayoutResponseFailure()` - 處理 API 業務失敗（建立失敗紀錄 + 日誌 + 回失敗響應）
- `handlePayoutSuccess()` - 處理代付成功（建立成功紀錄 + 回成功響應）
- `createFailureResponse()` - 簡化版失敗響應（無紀錄、純訊息）

**DepositCallbackTrait.php** - 代收回調通用邏輯

> **狀態規則**：`checkDepositOrderStatus()` 只允許 `OrderStatusEnum::CREATED (0)` 接受回調修改；
> 其餘狀態（`SUCCESS (1)`、`FAILED (2)`、`DEPOSIT_FINISHED (3)`、`WAITING_MANUAL_DEPOSIT (4)`）皆視為**回調終態**，
> 會拋出 `DepositOrderException(code=200)` 讓金流商收到成功響應停止重試。
>
> 注意「回調終態」≠「業務終態」：`SUCCESS (1)` 是回調已驗證的中間狀態，後續由 `PaymentService` 流程推進至業務終態
> `DEPOSIT_FINISHED (3)`（即 UI 顯示的「已上分」）。詳見 [2-開發金流商Driver.md「代收訂單狀態流轉」](2-開發金流商Driver.md)。
> 代付的回調放行規則見 [2-開發金流商Driver.md「代付訂單狀態與回調放行規則」](2-開發金流商Driver.md)。

- `findAndLockDepositOrder()` - 查詢並鎖定訂單，附帶日誌 context
- `checkDepositOrderStatus()` - 檢查訂單狀態，非 CREATED 拋 `DepositOrderException`
- `handleDepositOrderException()` - 統一處理訂單狀態異常（code=200 視為冪等成功）
- `updateDepositOrderSuccess()` - 將訂單推進至 `SUCCESS (1)`（**回調驗證完成的中間狀態**，非最終「已上分」狀態 `DEPOSIT_FINISHED (3)`）；金額不符時自動轉 `WAITING_MANUAL_DEPOSIT (4)`
- `updateDepositOrderFailed()` - 更新訂單為失敗
- `buildDepositSuccessResponse()` - 建立代收回調成功響應
- `buildDepositFailResponse()` - 建立代收回調失敗響應（可選帶 log）

**WithdrawalCallbackTrait.php** - 代付回調通用邏輯

> **狀態規則**：回調能不能處理分兩關。第一關 `checkWithdrawalOrderStatus()` 看訂單，只放行 21、22，
> 29 與其他狀態一律拒絕（400）並告警。第二關 `isPayoutRecordProcessed()` 看**代付紀錄本身**的
> `is_success_payout`，是 `SUCCESS` 才算處理過；不可改看訂單狀態，否則一張訂單有多筆代付紀錄時，
> 其餘紀錄的成功回調會被靜默吞掉。
> 詳見 [2-開發金流商Driver.md「代付訂單狀態與回調放行規則」](2-開發金流商Driver.md)。

- `findAndLockPayoutRecord()` - 透過我方訂單號查詢並鎖定代付請求記錄
- `findAndLockPayoutRecordByThirdPartyNo()` - 透過三方訂單號 + 我方訂單號雙重比對查詢
- `isPayoutRecordProcessed()` - 檢查該筆代付記錄是否已處理（看記錄自己的 `is_success_payout`，不看訂單狀態）
- `findAndLockWithdrawalOrderByPayoutRecord()` - 透過 payout record 查詢並鎖定提款訂單
- `updatePayoutRecord()` - 更新代付請求記錄
- `updateWithdrawalOrderStatus()` - 更新訂單狀態並處理交易日誌
- `validateCallbackAmount()` - 驗證回調金額是否匹配（自動記錄和通知）
- `logCallbackProcessed()` - 記錄回調處理日誌
- `buildWithdrawalSuccessResponse()` - 建立代付回調成功響應
- `buildWithdrawalFailResponse()` - 建立代付回調失敗響應（可選帶 log）
- `handleWithdrawalOrderException()` - 統一處理訂單狀態異常（code=200 視為冪等成功）

## 配置範例：EpicPay（代收 + 代付）

以下片段節錄自現行設定檔（EpicPay 代收 77、代付 78），完整寫法以實際檔案為準。

### 1. Data/cash_flows.php

```php
[
    'id' => 77,
    'third_party_code' => 'D_EPICPAY',  // 必填：sync 靠它（去掉 D_/W_ 前綴）找 providers/ 底下的設定檔
    'name' => 'EpicPay - Deposit',
    'rate' => '1.00000',
    'percentage' => '0.00000',
    'type' => 1,  // 代收
    'remark' => '',
    'info' => [
        'MYR' => ['rate' => 1, 'min_amount' => 10, 'max_amount' => 50000],
    ],
],
[
    'id' => 78,
    'third_party_code' => 'W_EPICPAY',
    'name' => 'EpicPay - Withdrawal',
    'rate' => '1.00000',
    'percentage' => '0.00000',
    'type' => 3,  // 代付
    'remark' => '',
    'info' => [
        'MYR' => ['rate' => 1, 'min_amount' => 100, 'max_amount' => 30000],
    ],
],
```

### 2. Data/providers/EpicPay.php

一個金流商一個檔，代收與代付分成 `deposit`、`withdrawal` 兩區：

```php
return [
    'deposit' => [
        'cash_flow_id' => 77,
        'channels' => [
            [
                'currency' => 'MYR',
                'name' => 'EpicPay (Banking)',
                'key' => 'EpicPay.Banking',
                'type' => DepositTypeEnum::ONLINE_PAYMENT->value,
                'image_path' => '',
                'options' => [
                    ['name' => 'MayBank', 'key' => 'MBB'],
                    ['name' => 'CIMB Bank', 'key' => 'CIMB'],
                ],
            ],
        ],
    ],
    'withdrawal' => [
        'cash_flow_id' => 78,
        'channels' => [
            [
                'currency' => 'MYR',
                'type' => WithdrawalTypeEnum::BANK,
                'banks' => [
                    ['name' => '(MYR) - Maybank', 'code' => 'MBB'],
                    ['name' => '(MYR) - CIMB Bank', 'code' => 'CIMB'],
                ],
            ],
        ],
    ],
];
```

### 3. 執行命令（推薦順序）

```bash
# ======== 階段一：配置與資料庫 ========

# 1. 編輯配置文件（手動）
# - Data/cash_flows.php
# - Data/providers/EpicPay.php

# 2. 同步 CashFlow（測試模式）
php artisan cash-flow:sync --ids=77,78 --dry-run

# 3. 同步 CashFlow（正式執行）
php artisan cash-flow:sync --ids=77,78

# 💡 使用幣別過濾（推薦逐步接入）
php artisan cash-flow:sync --ids=77,78 --currency=VND --dry-run  # 先預覽
php artisan cash-flow:sync --ids=77,78 --currency=VND            # VND 正式
php artisan cash-flow:sync --ids=77,78 --currency=THB            # 再接入 THB

# ======== 階段二：建立商戶配置 ========

# 4. 建立代理配置（代收，測試）
php artisan agent:add-agent-cash-flow --agent=4249 --cashflow=77 --currency=1 --mode=split --dry-run

# 5. 建立代理配置（代收，正式）
php artisan agent:add-agent-cash-flow --agent=4249 --cashflow=77 --currency=1 --mode=split

# 6. 建立代理配置（代付，測試）
php artisan agent:add-agent-cash-flow --agent=4249 --cashflow=78 --currency=1 --dry-run

# 7. 建立代理配置（代付，正式）
php artisan agent:add-agent-cash-flow --agent=4249 --cashflow=78 --currency=1

# 🚀 使用自動化命令（推薦多代理時使用）
php artisan cash-flow:auto-sync --cashflow=77,78 --currency=VND --dry-run
php artisan cash-flow:auto-sync --cashflow=77,78 --currency=VND

# ======== 階段三：實作 API 串接 ========

# 8. 編輯 config/payment.php（手動）
# provider => [
#     'EPICPAY' => Providers\EpicPay\Driver::class,
# ]

# 9. 建立 Provider 架構
php artisan make:payment EpicPay

# 10. 實作業務邏輯（手動）
# - Driver.php
# - Deposit.php / DepositCallback.php
# - Withdrawal.php / WithdrawalCallback.php
# - EpicPayTrait.php
```
