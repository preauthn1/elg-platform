> ← [金流商接入完整操作流程](index.md)

但最主要的目的是用來決定當前的金流商要使用的 Id 為何。

```bash
php artisan cash-flow:list
```

## 步驟二：登記 CashFlow 配置

### 基本說明

在 `app/Console/Commands/CashFlow/Data/cash_flows.php` 中登記金流商的基礎資料與幣別限制。

- ⚠️ 如果金流商同時支援代收和代付，需要建立兩筆記錄（不同 ID）
- ⚠️ `info` 中的金額限制為預設值，可在 OrderType 層級覆蓋

> app/Console/Commands/CashFlow/Data/cash_flows.php
```php
<?php

return [
    // ...existing cash flows...
    
    [
        'id' => 99,  // 使用未被佔用的 ID
        'third_party_code' => 'D_EPICPAY',  // 必填：D_ 代收、W_ 代付，後面接金流商名稱
        'name' => 'EpicPay - Deposit',
        'rate' => '1.00000',
        'percentage' => '0.00000',
        'type' => 1,  // 1: 代收, 3: 代付
        'remark' => '',
        'info' => [
            // 各幣別配置
            'MYR' => [
                'rate' => 1,           // 匯率
                'min_amount' => 10,    // 最小金額
                'max_amount' => 50000, // 最大金額
            ],
            'THB' => [
                'rate' => 1,
                'min_amount' => 100,
                'max_amount' => 500000,
            ],
        ],
    ],
];
```

**你負責**：
- **ID 唯一性**：確保 `id` 不與現有金流商重複。如果同時支援代收和代付，需建立兩筆不同 ID 的記錄
- **基礎定義**：正確設定 `name`、`type` (1=代收, 3=代付)
- **`third_party_code` 必填**：`cash-flow:sync` 靠它（去掉 `D_`／`W_` 前綴）找 `Data/providers/` 底下對應的設定檔；漏填的話這筆會被直接跳過，代收渠道與代付銀行都不會建立
- **金額限制**：在 `info` 中設定各幣別的預設匯率與出入金限制（此設定可被步驟三的渠道配置覆蓋）

說明

| 欄位                    | 類型     | 必填 | 說明               |
|-----------------------|--------|----|------------------|
| `id`                  | int    | ✓  | CashFlow ID，必須唯一 |
| `name`                | string | ✓  | 金流商名稱            |
| `type`                | int    | ✓  | 1=代收, 3=代付       |
| `status`              | int    | ✓  | 1=啟用, 0=停用       |
| `info`                | array  | ✓  | 幣別配置             |
| `info[幣別].rate`       | float  | -  | 匯率，預設 1          |
| `info[幣別].min_amount` | float  | -  | 最小金額             |
| `info[幣別].max_amount` | float  | -  | 最大金額             |


### 驗證

登記完成後可再一次輸入指令[`cash-flow:list`](../commands/cash-flow-list.md)，確認剛剛登記的金流商資料有成功顯示。

> 支援 `--type` 類別過濾、`--ids` 指定 id 等完整選項，詳見 [`cash-flow:list 指令說明`](../commands/cash-flow-list.md)。

## 步驟三：設定渠道配置

### 基本說明

建立金流商專屬的 Provider 配置文件，定義詳細的支付渠道或支援銀行清單。

#### 1. 銀行資料檢查（針對代付/洗分）

在配置前，需確認系統中是否已有對應的銀行名稱，避免重複建立導致資料污染。

**你負責**：
- 使用 SQL 或後台查詢現有銀行：
  ```sql
  SELECT name FROM banks WHERE name like '%GXS%' and agent_group_id=(SELECT cash_flow_group_id FROM agents WHERE username='frank');
  ```
- **沿用原則**：若名稱僅有細微差異（如空格、大小寫），請**直接沿用現有名稱**

#### 2. 建立 Provider 配置文件

在 `app/Console/Commands/CashFlow/Data/providers/` 目錄下建立金流商配置文件，以 `EpicPay` 為例：

> app/Console/Commands/CashFlow/Data/providers/EpicPay.php
```php
<?php

declare(strict_types=1);

use App\Enums\DepositTypeEnum;
use App\Enums\WithdrawalTypeEnum;

/**
 * EpicPay 金流商配置
 */
return [
    // === 代收配置 ===
    'deposit' => [
        'cash_flow_id' => 99,  // 對應 cash_flows.php 中的 ID
        'channels' => [
            // QR Code 支付
            [
                'currency' => 'MYR',
                'name' => 'EpicPay (QR)',
                'key' => 'EpicPay.QR',
                'type' => DepositTypeEnum::QRCODE->value,
                'image_path' => '',
                'min_amount' => 10,
                'max_amount' => 30000,
                'options' => [
                    ['name' => 'TnG QR', 'key' => 'TNGQR'],
                    ['name' => 'Duitnow QR', 'key' => 'DUITNOW'],
                ],
            ],
            
            // FPX 網銀支付
            [
                'currency' => 'MYR',
                'name' => 'EpicPay (FPX)',
                'key' => 'EpicPay.FPX',
                'type' => DepositTypeEnum::ONLINE_PAYMENT->value,
                'image_path' => '',
                'min_amount' => 50,
                'max_amount' => 30000,
                'options' => [
                    ['name' => 'FPX Internet Banking', 'key' => 'FPX'],
                    ['name' => 'FPX Duitnow QR', 'key' => 'FPXDUITNOW'],
                ],
            ],
        ],
    ],
    
    // === 代付配置（可選）===
    'withdrawal' => [
        'cash_flow_id' => 100,  // 代付的 CashFlow ID
        'channels' => [
            [
                'currency' => 'MYR',
                'type' => WithdrawalTypeEnum::BANK,
                'banks' => [
                    ['name' => 'Maybank', 'code' => 'MBB'],
                    ['name' => 'CIMB Bank', 'code' => 'CIMB'],
                    ['name' => 'Public Bank', 'code' => 'PBB'],
                    ['name' => 'RHB Bank', 'code' => 'RHB'],
                    ['name' => 'Hong Leong Bank', 'code' => 'HLB'],
                    // ...更多銀行
                ],
            ],
        ],
    ],
];
```

**你負責**：
- **代收渠道 (`deposit`)**：定義各幣別下的支付方式，指定 `key`（供 Driver 辨識）與 `type`
- **代付銀行 (`withdrawal`)**：定義支援的銀行清單，並填寫**金流商定義的銀行代碼** (`code`)

#### 代收渠道配置說明

這邊的資料經過腳本處理後，會寫入資料表 `order_types`

| 欄位           | 類型     | 必填 | 說明                                  |
|--------------|--------|----|-------------------------------------|
| `currency`   | string | ✓  | 幣別代碼（MYR/THB/VND 等）                 |
| `name`       | string | ✓  | 渠道顯示名稱                              |
| `key`        | string | ✓  | 渠道識別代碼                              |
| `type`       | int    | ✓  | 支付類型（`DepositTypeEnum::QRCODE` 等）   |
| `image_path` | string | -  | 渠道圖片路徑                              |
| `min_amount` | int    | -  | 最小金額（可覆蓋 cash_flows.php 的設定）         |
| `max_amount` | int    | -  | 最大金額（可覆蓋 cash_flows.php 的設定）         |
| `options`    | array  | -  | 銀行選項列表（網銀支付用），格式：`[name, key]` 陣列  |

#### 代付銀行配置說明

這邊的資料經過腳本處理後，會寫入資料表 `cash_flow_banks`

| 欄位           | 類型              | 必填 | 說明                                    |
|--------------|-----------------|----|-----------------------------------------|
| `currency`   | string          | ✓  | 幣別代碼                                  |
| `type`       | WithdrawalTypeEnum | ✓  | 銀行類型（如 `WithdrawalTypeEnum::BANK`）  |
| `banks`      | array           | ✓  | 銀行列表                                  |
| `banks.name` | string          | ✓  | 銀行名稱                                  |
| `banks.code` | string          | ✓  | 金流商定義的銀行代碼（如 `MBB`、`CIMB`）           |

### 基本說明

將 `cash_flows.php` 與渠道配置同步至資料庫。

```bash
# 測試模式（執行後回滾，不寫入）
php artisan cash-flow:sync --dry-run --ids=99,100

# 正式執行
php artisan cash-flow:sync --ids=99,100
```

- 執行指令並確認無誤
- **驗證數據**：使用 SQL 檢查 `cash_flows`、`order_types` 與 `cash_flow_banks` 是否正確寫入

## 步驟五：建立代理商戶配置

### 基本說明

完成金流商配置後，需要為代理建立商戶配置（`AgentCashFlow`），讓代理可以使用該金流商。

```bash
# 互動式執行
php artisan agent:add-agent-cash-flow

# 非互動式執行
php artisan agent:add-agent-cash-flow --agent=4249 --cashflow=99 --currency=MYR --mode=split
```

代收要選建立形式：`--mode=split` 是一個支付通道一筆商戶、各自設成本，`--mode=single` 是多個通道共用一筆商戶與同一個成本；不帶時會互動詢問。既有單筆記錄要改成拆分形式時加 `--migrate-single`。

**你負責**：
- 執行指令，指定正確的代理與金流商
- **驗證配置**：檢查 `agent_cash_flows` 表中的 `info` (密鑰) 是否正確

## 章節檢查清單

- [ ] **步驟二**：登記 `Data/cash_flows.php`
    - [ ] CashFlow ID 唯一且未被佔用
    - [ ] 設定正確的 type（1=代收, 3=代付）
    - [ ] 填了 `third_party_code`（`D_` 代收、`W_` 代付）
    - [ ] 配置各幣別的預設匯率和金額限制
- [ ] **步驟三**：設定渠道配置 `Data/providers/{Provider}.php`
    - [ ] 代收渠道 (deposit) 配置完整（name, key, type, currency）
    - [ ] 金額限制 (min/max_amount) 設定正確
    - [ ] 代付銀行 (withdrawal) 配置完整且包含正確的銀行代碼（如需要）
- [ ] **步驟四**：執行同步 `php artisan cash-flow:sync`
    - [ ] 先用 `--dry-run` 模式驗證無誤
    - [ ] 正式執行後，資料庫 `cash_flows`、`order_types` 等表數據正確寫入
- [ ] **步驟五**：建立代理商戶配置 `php artisan agent:add-agent-cash-flow`
    - [ ] 指定正確的 agent、cashflow、currency
    - [ ] 確認 `agent_cash_flows` 與 `agent_cash_flow_order_types` 建立成功
    - [ ] 代理後台能正確看到該金流商選項
