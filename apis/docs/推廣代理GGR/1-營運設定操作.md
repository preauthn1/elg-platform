# 1. 營運設定操作

三個頁面要**依序**設定：先有遊戲商設置與條件設置，才能建立方案把它們綁起來。三者都在「代理模式管理 > 推廣代理」底下。

## 1.1 代理遊戲商設置

決定「每一筆注單的 GGR 要不要算、算多少」。

一組設置底下，每個遊戲商 × 遊戲類型可以有多個階層。填法：

| 欄位 | 意思 | 填 0 的意思 |
|---|---|---|
| 計算金額 | 階梯門檻。單筆 GGR 取絕對值後達到這個值，才適用這一階 | 全收（不設門檻） |
| 最低遊戲輸贏 | 加權後的金額低於這個值就不計入 | 不限制 |
| 最大 GGR | 加權後的金額超過這個值就截斷 | 無上限 |
| 加權 (%) | 該階的加權比例 | 該階注單一律算 0 |
| 排除遊戲 | 這些遊戲的注單不列入 | — |
| 開關 | 關掉整個組合都不列入結算 | — |

**逐筆怎麼判**：取單筆 GGR 的絕對值，從**高階往低階**找第一個達標的階；連最低階都達不到，**整筆不計**。找到階之後保留原本的正負號乘上加權%，再過「最低遊戲輸贏」與「最大 GGR」兩道門檻（都看絕對值，截斷時保留正負）。

三個要注意的地方：

- **同一組合的各階門檻必須逐階遞增**，重複值會被擋下並提示哪一行重複。
- **階梯是「每筆注單」各自判定**，不是把整天加總後再落階。同一遊戲商的不同注單可能落在不同階。
- **遊戲商清單是「該總代實際開通的」**，沿著代理階層由近到遠繼承第一個有設定的層級；遊戲商或商戶被停用就不會出現。

## 1.2 代理條件設置

決定「這個代理這期能拿幾 %」。

一組條件底下有多個階，每階填五個門檻與一個應得百分比：

| 欄位 | 意思 |
|---|---|
| 用戶人數 | **必要條件**。合格會員數達到這個值才命中這一階。`0` 或留空＝不限制人數（但仍需至少 1 位合格會員） |
| 存款 / 總投注金額 / 遊戲總收入 / 有效流水 | 四項金額門檻，**每位會員各自**要達成，不是全體加總。`0` 或留空＝該項無要求 |
| 應得百分比 (%) | 命中這一階時代理拿的百分比 |
| 條件組合方式 | 四項金額門檻要「或者」還是「和」。全 OR 或全 AND，不混用 |
| 僅計算活躍用戶 | 開啟時只算活躍會員（充值與有效流水都達到個性化組別設定的門檻，設定位置：個性化組別 › 代理後台設置的「判斷活躍玩家條件(充值)」與「判斷活躍玩家條件(有效流水)」） |

**怎麼命中**：逐一檢核代理旗下每位直屬會員（已先扣掉被方案「帳戶驗證限制」排除的會員，見 1.3）的四項門檻，數出合格人數，然後**從最高階往下找第一個「合格人數 ≥ 用戶人數」的階**，取它的應得百分比。一階都沒達成 → **這個代理這期不產生任何結算紀錄**。

兩個容易誤會的點：

- **旗下 0 位會員的代理不會命中任何階**，即使門檻全部留空。
- 用戶人數填 0 不代表「無條件達成」——金額門檻還是要有人達標。只有「用戶人數與四項金額全部為 0」時才等於無條件達成。

標題在同一個總代內不可重複，重複會提示「標題已存在」。

## 1.3 代理 GGR 設置（方案）

把上面兩者綁起來，並決定費率與適用範圍。

**基本資料**

| 欄位 | 說明 |
|---|---|
| 類型 | 每日／每週／每月。**改這個只對下一期生效**，當期照原週期跑完 |
| 狀態 | 停用是唯一的止血手段：停用後尚未發放的結算列不會入帳 |
| 代理群組 | 決定適用哪些代理。**同一個總代、同一個群組同時只能有一個啟用中的方案** |
| GGR 標題 | 方案名稱 |
| 開始日期 | 這個方案從哪個業務日開始算帳。**不可填過去的日期**（見下方陷阱） |
| 發揚（負數結轉） | 開＝當期負數累積到下期並先沖抵；關＝期末負數歸 0 |

**金額設定**

| 欄位 | 說明 |
|---|---|
| 管理費 (%) | 從分潤後金額抽，不是從原始 GGR 抽 |
| 手續費 | 固定金額，**每次結算扣一次** |
| GGR 百分比 (%) | 方案自己的分潤比例，會與條件設置的應得百分比連乘 |
| 獎金百分比 (%) | 套在獎金基數上的比例 |

填完 GGR 百分比後，畫面會即時顯示一行唯讀試算：

> 有效分潤率：15%（條件設置應得百分比 50% × 代理設置 GGR% 30%）
> 判斷值需大於 1,404 才足以支付固定手續費 200

這行只是算給人看，不影響任何計算。條件設置有多階時取**最高階**的百分比試算。

**成員下線設置**：綁一組遊戲商設置與一組條件設置，適用群組內所有代理。可以在旁邊直接開新增彈窗建立，建好會自動選中。

**特殊用戶設定**：針對個別代理覆寫上面兩顆綁定。被指定的代理必須在該總代線內。

**帳戶驗證限制**：決定哪些直屬會員能算進這個方案的結算。有五個開關，加一個違規次數：

| 欄位 | 開啟後檢查什麼 |
|---|---|
| 銀行帳號唯一 | 會員啟用中的銀行帳號，跟同一代理的其他直屬會員重複 |
| 手機號碼唯一 | 手機號碼重複 |
| 信箱唯一 | 信箱重複 |
| IP 唯一 | 註冊 IP 重複 |
| 姓名唯一 | 姓名重複 |
| 違規次數 | 會員撞到幾個已開啟的項目就記幾次違規，達到這個次數就排除。`0`＝不限制 |

怎麼判：

- 比對範圍只在**同一個代理的直屬會員之間**，不跨代理線，也不掃全站。
- 每個開啟的項目最多記 1 次違規。同一位會員有兩個銀行帳號都跟別人重複，仍只算 1 次。
- 沒填的資料（空值、空字串、註冊 IP 為 0）不算撞值。
- 違規次數填 `0`，或五個開關都沒開，就完全不篩。違規次數不可以大於已開啟的開關數，存檔時會擋下。
- 被排除的會員在條件判定、GGR 與獎金三處都不算，三處用同一份名單。結算詳情的計算明細會記下直屬會員總數與被排除的人數。

方案**沒有**「領取前驗證」：不檢查會員是否完成銀行、信箱、手機或個人資料驗證。

## 1.4 設定陷阱

這幾項都是實際會造成金額異常的設定組合。

**兩個百分比連乘會讓分潤掉很快。** 50% 配 30% 只剩 15%，20% 配 30% 只剩 6%。而手續費是固定金額，很容易把小代理的正業績吃成負數——判斷值 1,920、有效分潤率 6% 的話，`1920 × 6% − 5.76 − 200 ＝ −90.56`。這是預期行為，系統不做「不得為負」的保護，設定時要看畫面上的損益兩平點。

**改成日結時手續費要重新評估。** 手續費每次結算扣一次，不隨週期換算。同樣填 200，月結一個月扣 200，日結一個月扣約 6,000。切換週期時務必同步調小手續費。

**開始日期不可回填過去。** 系統會擋（提示日期須為今日或之後）。理由是回填會讓方案第一輪一次補出從該日起的所有歷史期間，每期都用真實歷史注單算出金額，並在下一輪發放時全部入帳；而已發放的紀錄不能靠重跑修正、交易紀錄也沒有沖銷型別，錯誤金額無法由系統回收。要補算歷史請走 Olympus 的結算補跑（帶截至日）。

**同一群組只能有一個啟用方案。** 因為遞延餘額是跟著代理走的，同一個代理若被兩個方案同期結算，同一筆負餘額會被沖抵兩次。建立或啟用第二個方案時會提示「該代理群組已有啟用中的方案」。

**方案只結算總代線內的代理。** 個性化組別是全站共用的，同一個群組可能同時掛著不同總代線下的代理。系統只結算「群組相符 **且** 在方案總代線內」的代理，所以群組裡有 200 位代理不代表 200 位都會被結算。

**綁定的設定被停用時，該代理整個跳過。** 停用遊戲商設置或條件設置不會斷開既有方案的引用（只是不能再新選），但結算時會跳過吃到該設定的代理、不產生紀錄。
