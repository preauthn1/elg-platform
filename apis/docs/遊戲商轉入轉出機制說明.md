# 遊戲商轉入轉出機制說明

## 概述
所有第三方回傳值都要檢查，並且在完全確認結果時才能繼續後續行為

### 轉出至遊戲商：
1. 明確並嚴謹的定義成功交易邏輯
2. 明確並嚴謹的定義失敗交易邏輯 (交易失敗退還玩家分數)
3. 其他情況 (交易失敗/逾時/伺服器錯誤，不退還玩家分數)
4. 特殊情況 (交易失敗，但需隔一段時間重新檢查，先列出後討論)
  
### 遊戲商轉入平台：  
1. 明確並嚴謹的定義成功交易邏輯 (交易成功增加玩家分數)
2. 明確並嚴謹的定義失敗交易邏輯 (交易失敗不增加玩家分數)
3. 其他情況 (交易失敗/逾時/伺服器錯誤，不增加玩家分數)

## 還錢機制
系統會先把玩家的錢扣掉並做好紀錄後，再呼叫第三方 API，並根據 API 回傳值判斷後續行為：

| 新版 APIs 回傳值 (\<vendor_name>/Driver.php) | 舊版 API_Frontend 回傳值 (Vendor\<vendor_name>) | 後續行為 |
| --- | --- | --- |
| SUCCESS | true (bool) | DB::commit(), 繼續執行 |
| FAILED  | 在弱型別判斷下**不等於**空字串的值 | DB::rollBack(), 還錢並回傳 error |
| TIMEOUT | 空字串 or false or 0 等在弱型別判斷下**等於**空字串的值 | transaction_log 紀錄失敗, **不會還錢** |

## 詳述
可參考以下 (DG, APIs)
```php
$result = Http::logAction('Dg_CheckTransferStatus', $postData)
    ->asJson()
    ->post($url, $postData)
    ->throw()
    ->json();

// 不確定結果, 不還錢
if (!is_array($result)) {
    \Log::error('[Dg][CheckTransferStatus] API error: response data is not array.', $logData);

    return VendorTransferResultEnum::TIMEOUT;
}

// 無法確定結果, 不還錢
if (!isset($result['codeId'])) {
    \Log::error('[Dg][CheckTransferStatus] API error: response data is not correct.', $logData);

    return VendorTransferResultEnum::TIMEOUT;
}

if ((int) $result['codeId'] === 0) {
    // 完全確定該單成功
    return VendorTransferResultEnum::SUCCESS;
} elseif ((int) $result['codeId'] === 324) {
    // 完全確定該單失敗
    return VendorTransferResultEnum::FAILED;
}

// 無法明確確定結果, 不還錢
return VendorTransferResultEnum::TIMEOUT;
```

### 備註
1. 無法確定結果的情況，務必 **當作不還錢** 處理，如果 throw Exception 會直接還錢，但我方不知道第三方到底狀況是怎樣，所以錢應該要扣下來做複查 (如果 throw 了並還錢後續有狀況還比較難查，算做 timeout 至少可以用 checkTransferStatus 來做複查)
2. **複查行為**是 `APIs` 才會有
3. `API_Frontend` 對於轉帳錢包的還錢判定只用了 `$rs != ''` 來確定要不要還錢，所以比較舊的遊戲商會回傳空字串 or false 來把錢扣住，回傳 array 來還錢
