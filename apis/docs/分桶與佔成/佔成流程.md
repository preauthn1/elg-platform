# 佔成流程

> 以 `**SP_calc_profit_share**`（結算／寫入業績與中繼）與 `**SP_payout_profit_share**`（派彩／寫帳務紀錄）為核心，**由派彩往回反推**到 `summary_bet_records`，並說明何時寫入 `**wallet_transaction_log_agents`** 與 `**transaction_log_agents**`。

---

## 一、核心 SP 分工


| SP                           | 角色                                                                                    | 與 `summary_bet_records`                                                                                    | 與兩張 log 表                                                          |
| ---------------------------- | ------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------ |
| `**SP_calc_profit_share**`   | 佔成**結算**：建中繼、WHILE 階層、寫 `**summary_profit_shares`**，更新 `**profit_share_payout_logs**` | **不**讀 `summary_bet_records`；讀 `**summary_profit_share_winloses`**（該表來自下游的 `SP_calc_profit_share_winlose`） | **不**寫入 `wallet_transaction_log_agents` 或 `transaction_log_agents` |
| `**SP_payout_profit_share`** | 佔成**派彩**：依 `summary_profit_shares` 對子代理撥款                                             | **不**讀 `summary_bet_records`                                                                               | 依 `**TotalProfit`** 分支寫入其中一種（見第三節）                                 |


投注來源與 `summary_profit_share_winloses` 的銜接在 `**SP_calc_profit_share_winlose**`（見第二節末）。

---

## 二、反推：從派彩端往回走

### 2.1 起點 — `SP_payout_profit_share`

1. **鎖定與 gate**
  - `SELECT ... FROM profit_share_payout_logs WHERE id = PayoutRecordId FOR UPDATE`  
  - 僅當 `**status = 4`** 才繼續；否則 `ROLLBACK` 並通知「重複觸發攔截」。  
  - 註：`SP_calc_profit_share` 結束時將同一筆 log 設為 `**status = 3**`，因此 **3 → 4** 的推進發生在本兩支 SP **之外**（例如後台／排程／其他程式），須併入實際營運流程。
2. **派彩清單來源**
  Cursor 自 `**summary_profit_shares`**：  
  - `summary_time` 在當期 `StartTime`～`EndTime`  
  - `**status = 0**`  
  - `**profit != 0**`（再於子查詢聚合 `direct_profit`、`team_profit`、`profit`）  
  - 代理須在總代 `hierarchy_path` 下，且 **排除總代本人**（`agent_id != AgentId`）。
3. **每個子代理一筆 `TotalProfit`**
  `TotalProfit = SUM(direct_profit) + SUM(team_profit) + SUM(profit)`（與 cursor 欄位定義一致）。
4. **寫入兩張 log 的分歧（關鍵）** — 僅當子代理 `**is_balance_unlimited = 0`** 時進入撥款邏輯：

  | 條件                             | 寫入表                                 | 主要欄位／行為                                                                                                                                                                                                                                              |
  | ------------------------------ | ----------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
  | `**TotalProfit < 0**`          | `**wallet_transaction_log_agents**` | `wallet_type_id = 3`（佔成錢包）、`type = 3`、`amount = TotalProfit`、`remark = '佔成結算'`；**不**更新總代 `agents.balance`（相關 `UPDATE agents` 已註解）；**會** `UPDATE agent_wallets`（佔成錢包加額，金額為負代表扣減方向由餘額欄位體現）。                                                            |
  | `**TotalProfit >= 0`**（`ELSE`） | `**transaction_log_agents**`        | `from_agent_id = AgentId`（總代）、`to_agent_id = ToAgentId`、`type = 9`（`TransactionType`）、`amount = TotalProfit`；`from_limit_of_credit` / `to_limit_of_credit` 使用 **派彩後**餘額（`GeneralAgentAfterBalance`、`AfterBalance`）；接著總代／子代理 `**agents.balance`** 互轉。 |

5. **收尾**
  - `summary_profit_shares`：`status = 0` → `**1`**（已派發）  
  - `profit_share_payout_logs`：`**5**`（派發中）→ `**1**`（已派發）  
  - `COMMIT`

### 2.2 往回 — `summary_profit_shares` 從哪裡來？

來自 `**SP_calc_profit_share**`（同一 `PayoutRecordId` / 總代 `AgentId` / 結算日）：

- 先將 `**profit_share_payout_logs**`：`status = 0` → `**2**`（結算中）。  
- 建立／更新 `**profit_share_settings**`、`**agent_temps**`、`**summary_profit_share_winlose_temps**`（自 `**summary_profit_share_winloses**` JOIN 類別設定，並 LEFT JOIN `**summary_profit_share_event_costs**`、`**summary_profit_share_payment_costs**` 做成本分攤）。  
- 重置後以 **WHILE** 依代理層級寫入／更新 `**summary_profit_shares`**（含 `direct_profit`、`team_profit`、`profit`、`weighting`、佔成錢包封頂等）。  
- 結束時 `**profit_share_payout_logs**`：`status = 2` → `**3**`（已結算；與 migration 註解用語可能不同，以 SP 內註解為準）。

### 2.3 再往回 — `summary_profit_share_winloses` 從哪裡來？

來自 `**SP_calc_profit_share_winlose**`（與結算日、各佔成總代樹相關）：

- **唯一**在佔成鏈中直接讀 `**summary_bet_records`**：  
  - 會員 `**previous_day_type = 2**`（佔成會員）  
  - `bet` → turnover、`win_lose`、`cost`，並對應 `**games.type_id**`（含 vendor 3/10/23 且 `game_id` 無對應時之 `game_type_id` 特例）
- 寫入 `**summary_profit_share_winloses**`，並可插入 `**profit_share_payout_logs**`（`status = 0`）若該期尚無紀錄。

### 2.4 成本與類別彙總（非兩支核心 SP 讀 sbr，但影響結算）

- `**SP_calc_profit_share_event_cost**` → `**summary_profit_share_event_costs**`  
- `**SP_calc_profit_share_payment_cost**` → `**summary_profit_share_payment_costs**`  
- 兩者由 `**SP_calc_profit_share**` 併入 `**summary_profit_share_winlose_temps**` 後再影響 `**summary_profit_shares**`。  
- `**SP_calc_profit_share_temp**` 寫入 `**summary_profit_share_temps**`：`SP_calc_profit_share` **未**引用該表，屬併行彙總／查核用途（重跑可搭配 `**SP_profit_share_reset`**）。

## 三、順向總覽（`summary_bet_records` → 兩張 log）

```text
summary_bet_records
    ↑ 僅佔成會員 previous_day_type = 2
SP_calc_profit_share_winlose
    → summary_profit_share_winloses
    → profit_share_payout_logs (status 0, 若無則 INSERT)

[選配] SP_calc_profit_share_event_cost / SP_calc_profit_share_payment_cost
    → summary_profit_share_event_costs / summary_profit_share_payment_costs

SP_calc_profit_share
    → profit_share_payout_logs (0→2→3)
    → summary_profit_share_winlose_temps → summary_profit_shares (status 0)

[系統外] profit_share_payout_logs (3→4)

SP_payout_profit_share
    ← summary_profit_shares (status=0, profit≠0)
    ← profit_share_payout_logs (status=4)
    → 若 TotalProfit < 0  → wallet_transaction_log_agents + agent_wallets
    → 若 TotalProfit ≥ 0 → transaction_log_agents + agents.balance
    → summary_profit_shares status=1 ; profit_share_payout_logs status=1
```

---

## 四、`profit_share_payout_logs.status`（依 SP 內註解）


| 值   | 意義（`SP_calc_profit_share` / `SP_payout_profit_share` 註解） |
| --- | -------------------------------------------------------- |
| 0   | 未派發（`SP_calc_profit_share_winlose` 可插入）                  |
| 2   | 結算中（`SP_calc_profit_share` 開頭）                           |
| 3   | 已結算（`SP_calc_profit_share` 結尾）                           |
| 4   | 已發佈數據（`**SP_payout_profit_share` 允許派彩的條件**）              |
| 5   | 派發中（派彩 SP 內短暫狀態）                                         |
| 1   | 已派發（派彩成功結束）                                              |


派彩失敗時，`SP_payout_profit_share` 的 exception handler 會嘗試將 `**status = 5`** 改回 `**4**`（與重試語意一致）。
