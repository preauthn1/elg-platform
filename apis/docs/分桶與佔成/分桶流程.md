# 分桶流程

> 以 **`SP_calc_shareholder2`**（分桶結算、階層與股份級差）與 **`SP_shareholder_payout2`**（分桶派彩、主錢包額度轉移）為核心，**由派彩往回反推**到投注彙總來源；並標示與 **`wallet_transaction_log_agents`** 的關係（本分桶派彩 **不**寫入該表）。

---

## 一、核心 SP 分工

| SP | 角色 | 讀取主資料 | 寫入／更新重點 |
|----|------|------------|----------------|
| **`SP_calc_shareholder2`** | **分桶結算**：建 `agent_temps`、`summary_shareholder_winlose_temps`，WHILE 階層計算後寫 **`summary_shareholders`**；結尾更新 **`shareholder_payout_logs`** | **`summary_shareholder_winloses`**（經中繼與 **`summary_shareholder_temps`**）、`shareholder_categories`、`agent_personal_settings`（`setting_id = 95001`）等 | **`summary_shareholders`**；**`shareholder_payout_logs.status`**（見第四節） |
| **`SP_shareholder_payout2`** | **分桶派彩**：總代與子代理間 **`agents.balance`** 轉帳 | **`summary_shareholders`**（`status = 0` 且 direct/team 獎金非零）、`agents` | **`transaction_log_agents`**（`type = 5`）；**`shareholder_payout_logs`**（派發中→已派發） |

**與佔成錢包：** `SP_shareholder_payout2` **僅**使用 **`transaction_log_agents`** 與 **`agents.balance`**，**不** INSERT **`wallet_transaction_log_agents`**、**不**操作 **`agent_wallets`**（佔成錢包 `wallet_type_id = 3` 為佔成模式 `SP_payout_profit_share` 路徑）。

## 二、反推：從派彩端往回走

### 2.1 起點 — `SP_shareholder_payout2`

1. **時間區間**  
   `SummaryDate`（預設為「系統日 UTC+8 的昨日」對應之日期）→ `StartTime = SummaryDate - 8h`，`EndTime = StartTime + 1 日 - 1 秒`。

2. **派彩清單（Cursor）** — 資料來自 **`summary_shareholders`**：  
   - `summary_time` 在 `StartTime`～`EndTime`  
   - **`status = 0`**  
   - **Direct 段**：`SUM(direct_nett_profit)`、`SUM(direct_win_nett_profit)`，條件 **`direct_nett_profit != 0`**  
   - **Team 段**：`SUM(team_nett_profit)`、`SUM(team_win_nett_profit)`，條件 **`team_nett_profit != 0`**，代理欄為 **`parent_id`**  
   - 兩段 **UNION** 後再依 `agent_id` 加總 → 每個子代理 **`BetNettProfit`**、**`WinNettProfit`**  
   - 僅保留在總代 **`hierarchy_path`** 樹下之代理，且 **排除總代本人**（`agent_id != AgentId`）。

3. **每筆子代理**  
   - **`NettProfit = BetNettProfit + WinNettProfit`**  
   - 若 **`BetNettProfit != 0`**：對 `ToAgentId`、總代 `AgentId` 之 **`agents`** `FOR UPDATE`，先插一筆 **`transaction_log_agents`**（總代 → 子代、`type = 5`（變數 `TransactionType`）、`amount = BetNettProfit`，`remark` 含雙方餘額變化說明）。  
   - 若 **`WinNettProfit != 0`**：再插第二筆 **`transaction_log_agents`**（同樣 `type = 5`，`amount = WinNettProfit`）。  
   - 若總代 **`is_balance_unlimited = 0`**：`UPDATE agents SET balance = balance - NettProfit WHERE id = AgentId`；並 **`UPDATE agents SET balance = balance + NettProfit WHERE id = ToAgentId`**。  
   - 子代理若 **`is_balance_unlimited = 1`**：整段撥款略過（不寫 log、不調餘額）。

4. **控制表**  
   - 開頭：`UPDATE shareholder_payout_logs SET status = 2 WHERE id = ShareholderPayoutLogId`（派發中）。  
   - 結尾：`UPDATE shareholder_payout_logs SET status = 1`（已派獎）。  
   - **注意：** 本 SP **未** UPDATE **`summary_shareholders.status`**；若業務需「已派彩」標記，須另有程式或 SP 處理。

### 2.2 往回 — `summary_shareholders` 從哪裡來？

來自 **`SP_calc_shareholder2`**（同一總代 `AgentId`、結算區間、`PayoutRecordId`）：

- 寫入 **`agent_temps`**（樹下代理層級）。  
- 由 **`summary_shareholder_winloses`** JOIN 類別設定，寫入 **`summary_shareholder_winlose_temps`**。  
- 可補齊下級 **`agent_personal_settings`**（`setting_id = 95001`，依上層與 `ShareholderAgencyGap` 遞減）。  
- **重置** 當期該總代樹下 **`summary_shareholders`** 多欄位後，以 **`WHILE ThisLevel > 1`** 依層寫入／更新 **`summary_shareholders`**（含 `direct_nett_profit`、`team_nett_profit`、`direct_win_nett_profit`、`team_win_nett_profit`、`nett_profit`、`remark` 等；計算會 JOIN **`summary_shareholder_temps`** 之 `share_point`、`bet_ratio`、`commission_ratio`、`nett_profit` 等）。

### 2.3 再往回 — `summary_shareholder_winloses` 與 `summary_shareholder_temps`

| 程序 | 作用 |
|------|------|
| **`SP_calc_shareholder_winlose2`** | 由 **`summary_bet_record_agents`** 彙總寫入 **`summary_shareholder_winloses`**；並對符合分桶開關（`setting_key = 6100`）之總代組別 **INSERT `shareholder_payout_logs`**（`status = 0`），若該 `summary_time`+`agent_group_id` 尚不存在。 |
| **`SP_calc_shareholder_temp2`** | 讀 **`summary_shareholder_winloses`** 與 `shareholder_categories` 等，寫入 **`summary_shareholder_temps`**；檔案末尾並 **`UPDATE shareholder_payout_logs SET status = 3 WHERE id = PayoutRecordId AND status = 0`**（與 SP 內註解「已輸入數據(未結算)」一致）。 |

### 2.4 回到投注彙總 — `summary_bet_records`

本核心兩支 SP **皆不**讀 **`summary_bet_records`**。鏈上第一個讀取會員逐筆投注彙總表的是 **`SP_summary_bet_record_by_agent`**：

- **輸入：** **`summary_bet_records`**（JOIN `members`、`agents`、`games`）。  
- **輸出：** **`summary_bet_record_agents`**（依代理、廠商、`game_type_id` 等聚合 `total_bet`、`total_win_lose`、`total_cost` 等）。

之後 **`SP_calc_shareholder_winlose2`** 才讀 **`summary_bet_record_agents`** 寫入 **`summary_shareholder_winloses`**。

## 三、順向總覽（`summary_bet_records` → `transaction_log_agents`）

```text
summary_bet_records
    ↓ SP_summary_bet_record_by_agent（非本文件兩支核心，但為實際前繼）
summary_bet_record_agents

SP_calc_shareholder_winlose2
    → summary_shareholder_winloses
    → shareholder_payout_logs（status 0，按組別開期）

SP_calc_shareholder_temp2
    → summary_shareholder_temps
    → shareholder_payout_logs（status：0 → 3，見第四節與 calc2 條件）

SP_calc_shareholder2
    → agent_temps、summary_shareholder_winlose_temps
    → summary_shareholders（待派彩列 cursor 使用 status = 0）
    → shareholder_payout_logs（status：見第四節）

SP_shareholder_payout2
    ← summary_shareholders（status = 0, 獎金條件）
    → transaction_log_agents（type = 5，可兩筆：投注分紅 + 業績分紅）
    → agents.balance
    → shareholder_payout_logs（2 → 1）
```

## 四、`shareholder_payout_logs.status`（SP 內註解與 migration）

**Migration**（`2025_06_19_091321_create_shareholder_payout_logs_table.php`）註解含一組期望流程：  
`0 → 3 → 5 → 6 → 4 → 2 → 1`（與各 SP 內單行註解用語略有出入，營運以實際呼叫順序為準）。

**本 repo 中與兩支核心相關的 SQL 行為：**

| 位置 | 行為 |
|------|------|
| `SP_calc_shareholder_winlose2` | `INSERT ... status = 0`（新期別） |
| `SP_calc_shareholder_temp2` 結尾 | `UPDATE ... SET status = 3 WHERE status = 0` |
| `SP_calc_shareholder2` 結尾 | `UPDATE ... SET status = 4 WHERE status IN (0, 6)` |
| `SP_shareholder_payout2` | 開始 `status = 2`，結束 `status = 1` |

**實務提醒：** 若同一 `PayoutRecordId` **先**跑完 `temp2`（`0→3`），則 **`SP_calc_shareholder2` 結尾條件 `status IN (0,6)` 不會命中 `3`**，該 UPDATE 可能不生效；實際上線順序與是否另有程式將狀態改回 `0`/`6` **請與 DBA／排程設定核對**。派彩端 **`SP_shareholder_payout2` 未檢查前置 status**，直接設為 `2`。

## 五、與「佔成流程」之差異（對照）

| 項目 | 分桶（本文件） | 佔成（`佔成流程.md`） |
|------|----------------|----------------------|
| 結算核心 SP | `SP_calc_shareholder2` | `SP_calc_profit_share` |
| 派彩核心 SP | `SP_shareholder_payout2` | `SP_payout_profit_share` |
| 讀取之投注彙總 | `summary_bet_record_agents`（來自 sbr） | `summary_bet_records`（佔成會員） |
| 派彩寫入 | 僅 **`transaction_log_agents`**（`type = 5`） | `TotalProfit < 0` → **`wallet_transaction_log_agents`**；否則 **`transaction_log_agents`**（`type = 9`） |
