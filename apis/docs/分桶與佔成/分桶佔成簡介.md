# 分桶與佔成 — 入門簡介

> 給**完全沒接觸過**這套制度的人看的白話說明。  
> 技術細節與 SP 欄位對照請見 [`分桶流程.md`](./分桶流程.md)、[`佔成流程.md`](./佔成流程.md)。

---

## 一、先講結論：這兩套制度在做什麼？

平台每天會彙總**會員投注**產生的營業額、輸贏、成本，算出「公司這天賺多少／虧多少」。  
代理體系不是只有一層，總代底下還有子代理、子代理底下還有會員。

**分桶**與**佔成**都是回答同一個問題：

> **會員投注產生的利益（或成本），要怎麼依代理階層切分、最後把錢撥給誰？**

|          | 分桶                                                       | 佔成                                                          |
| -------- | ---------------------------------------------------------- | ------------------------------------------------------------- |
| 核心概念 | 把公司利潤當成「桶子」，依**股份**與**業績佔比**分給各代理 | 依代理**佔成比例**，直接吃直屬／下級會員的**輸贏**            |
| 派彩錢包 | 總代 **主錢包** → 子代理主錢包                             | 賺錢走主錢包；**虧損**走 **佔成錢包**（`wallet_type_id = 3`） |
| 適用會員 | 僅 **`previous_day_type = 0`（一般會員）**                 | 僅 **`previous_day_type = 2`（佔成會員）**                    |

## 二、名詞速查

| 名詞                   | 白話                                                              |
| ---------------------- | ----------------------------------------------------------------- |
| **總代（GA）**         | 分桶／佔成結算的根節點；派彩時從總代帳上撥款給下線                |
| **股份 / share_point** | 代理在「可分配池」裡拿多少**份額**；數字越大分得越多              |
| **級差**               | 上層股份 − 下層股份；中間差額由上一層「吃掉」                     |
| **直屬（direct）**     | 該代理**自己**名下的會員業績                                      |
| **團隊（team）**       | **下級代理**及其會員的業績，由上一層依級差分配                    |
| **投注分紅**           | 依**營業額佔比**切分的那一桶（分桶 v2）                           |
| **業績分紅**           | 依**正淨利佔比**切分的那一桶（分桶 v2；公司該分類虧損時此桶為 0） |
| **Settlement**         | 後台手動輸入的公司成本／調整，會進分桶計算                        |

## 三、股份從哪裡來？

設定分兩張表，先記這個規則：

| 表                              | 識別方式                       | 典型用途                               |
| ------------------------------- | ------------------------------ | -------------------------------------- |
| **`agent_customized_settings`** | `setting_key`（如 6100、8001） | 組別級開關、總代股份上限、層級差額等   |
| **`agent_personal_settings`**   | `setting_id` **95001～95999**  | 各代理個人設定（股份、佔成錢包封頂等） |

> 下文表格中，`setting_key` 指 `agent_customized_settings`；`95001` 等數字指 `agent_personal_settings.setting_id`。

### 分桶（v1 / v2 共用）

| 設定         | 來源                        |  key / id | 誰設定   | 用途                                                             |
| ------------ | --------------------------- | --------: | -------- | ---------------------------------------------------------------- |
| 分桶開關     | `agent_customized_settings` |  **6100** | 總代組別 | 是否啟用分桶                                                     |
| 總代股份上限 | `agent_customized_settings` |  **8001** | 總代組別 | 全樹可分配份額的**分母**（例：130）                              |
| 層級差額     | `agent_customized_settings` |  **8004** | 總代組別 | 下級未設股份時，沿上層遞減的步長（`ShareholderAgencyGap`）       |
| 代理股份     | `agent_personal_settings`   | **95001** | 各代理   | 該代理拿幾份（例：100）                                          |
| 遊戲分類比例 | `shareholder_categories`    |         — | 後台     | v2 專用：`bet_ratio`（投注桶 %）、`commission_ratio`（業績桶 %） |

**直覺**：總代開了一個「130 份的大饼」，A 代理設定 100 份、B 代理 100 份……  
實際能分多少還要乘上**該代理營業額／淨利佔全公司多少**。

### 佔成

| 設定               | 來源                        |  key / id | 用途                                                        |
| ------------------ | --------------------------- | --------: | ----------------------------------------------------------- |
| 分桶／佔成開關     | `agent_customized_settings` |  **6100** | 是否啟用（佔成樹亦須開啟）                                  |
| 份桶模式           | `agent_customized_settings` |  **6102** | 值 = 1 時走佔成流程                                         |
| 公司佔成數         | `agent_customized_settings` |  **8201** | 公司保留成數設定                                            |
| 佔成點 share_point | `agent_personal_settings`   | **95001** | 階層標識、與下級的級差                                      |
| 佔成錢包封頂       | `agent_personal_settings`   | **95110** | 封頂額度（-1 = 不限）                                       |
| 直屬佔成 %         | `profit_share_agents`       |         — | 吃**自己會員**輸贏的成數                                    |
| 下級佔成 %         | `profit_share_agents`       |         — | 吃**下級代理**貢獻輸贏的成數                                |
| 佔成錢包餘額       | `agent_wallets`             |         — | `wallet_type_id = 3`；餘額不足時實拿獎金打折（`weighting`） |

**直覺**：佔成不是分「公司利潤桶」，而是問「這條線的會員輸了 10 萬，你設定吃 50%，就拿 5 萬」——  
但錢包只有 3 萬時，可能只實拿 3 萬。

## 四、三種模式差在哪？

| 項目           | 分桶 v1                             | 分桶 v2（2IN1）                               | 佔成                                                                         |
| -------------- | ----------------------------------- | --------------------------------------------- | ---------------------------------------------------------------------------- |
| 適用會員       | `previous_day_type = 0`             | 同左                                          | `previous_day_type = 2`                                                      |
| 版本           | 舊版，單桶                          | **現行主推**，雙桶                            | 另一套制度                                                                   |
| 分幾種獎金     | **1 種**（營業額／淨利混合池）      | **2 種**：投注分紅 + 業績分紅                 | **1 種**（輸贏佔成，含直屬＋團隊）                                           |
| 分配依據       | 營業額佔比 × 股份                   | 投注桶看營業額；業績桶看**正淨利**佔比 × 股份 | 會員輸贏 × 佔成 % × 錢包權重                                                 |
| 核心結算 SP    | `SP_calc_shareholder`               | `SP_calc_shareholder2`                        | `SP_calc_profit_share`                                                       |
| 核心派彩 SP    | `SP_shareholder_payout`             | `SP_shareholder_payout2`                      | `SP_payout_profit_share`                                                     |
| 派彩 log       | `transaction_log_agents` type **5** | type **5**（可拆兩筆：投注 + 業績）           | 賺：`transaction_log_agents` type **9**；虧：`wallet_transaction_log_agents` |

**記憶口訣**

- **v1**：只看「公司賺多少 + 你營業額占多少 + 你股份多少」→ 一筆獎金。
- **v2**：把公司利潤拆成**投注桶**與**業績桶**，分別算、分別派。
- **佔成**：不看公司桶子，看**會員輸贏**與**代理佔成 %**，且受佔成錢包封頂。

## 五、投注分紅 vs 業績分紅（分桶 v2 專屬）

僅 **分桶 v2** 會把同一分類的公司淨利拆成兩桶（比例由 `bet_ratio` / `commission_ratio` 決定，常見 60% / 40%）：

```
公司該分類淨利（nett_profit）
        │
        ├── 投注分紅池 = nett_profit × bet_ratio / (bet_ratio + commission_ratio)
        │       └── 依「代理營業額 / 總營業額」×「代理股份 / 總股份」分配
        │
        └── 業績分紅池 = nett_profit × commission_ratio / (...)   ← 僅當 nett_profit > 0
                └── 依「代理正淨利 / 總正淨利」×「代理股份 / 總股份」分配
                    （代理淨利 ≤ 0 者不進業績池）
```

派彩時 `SP_shareholder_payout2` 可各寫一筆 `transaction_log_agents`：

- **BetNettProfit** → 投注分紅
- **WinNettProfit** → 業績分紅

## 六、計算範例（同一組數字，三種算法）

以下皆為**簡化教學數字**，省略 Settlement、團隊級差、錢包封頂等細節。  
設定：總代股份分母 **130**，代理 A 股份 **100**。

### 情境設定

- 公司 SLOT 分類當日：**營業額 100 萬、淨利 3 萬**（會員整體輸 3 萬給公司）
- 代理 A：**營業額 60 萬（占 60%）**、**淨利 +1.5 萬（占正淨利 37.5%）**
- v2 分類比例：**投注 60% / 業績 40%**
- 佔成：A 代理 Live 類 **direct_percentage = 50%**；直屬會員當日輸 **10 萬**（公司贏 10 萬）
- 佔成錢包充足，`weighting = 1`

---

### 範例 1：分桶 v1

**公式**：`代理獎金 = 公司淨利 × 營業額佔比 × (代理股份 / 130)`

```
A 獎金 = 30,000 × 60% × (100 / 130)
       = 30,000 × 0.6 × 0.7692
       ≈ 13,846 元
```

→ 派彩 SP 彙總為一筆 `direct_nett_profit + team_nett_profit`，`SP_shareholder_payout` 寫入一筆 type 5。

---

### 範例 2：分桶 v2（2IN1）

**Step 1 — 拆桶**

| 桶         | 計算         |   金額 |
| ---------- | ------------ | -----: |
| 投注分紅池 | 30,000 × 60% | 18,000 |
| 業績分紅池 | 30,000 × 40% | 12,000 |

**Step 2 — 代理 A**

| 項目     | 計算                       |         金額 |
| -------- | -------------------------- | -----------: |
| 投注分紅 | 18,000 × 60% × (100/130)   |      ≈ 8,308 |
| 業績分紅 | 12,000 × 37.5% × (100/130) |      ≈ 3,462 |
| **合計** |                            | **≈ 11,770** |

→ `SP_shareholder_payout2` 可能拆成兩筆 type 5 分別撥款。

---

### 範例 3：佔成

**公式（直屬、簡化）**：`direct_profit = 會員輸贏（公司視角）× direct_percentage × weighting`

會員輸 10 萬 → 公司贏 10 萬：

```
A direct_profit = 100,000 × 50% × 1
                = 50,000 元
```

若當日 `direct_profit + team_profit` 合計 **≥ 0**：`SP_payout_profit_share` 從總代主錢包撥給 A。  
若合計 **< 0**（代理要承擔虧損）：改記 **`wallet_transaction_log_agents`**，從佔成錢包扣，不動總代主錢包。

---

### 三種算法對照（代理 A）

| 模式    | 看什麼                       |                        代理 A 約拿 |
| ------- | ---------------------------- | ---------------------------------: |
| 分桶 v1 | 公司淨利 × 營業額佔比 × 股份 |                           ≈ 13,846 |
| 分桶 v2 | 投注桶 + 業績桶 分開算       |                           ≈ 11,770 |
| 佔成    | 直屬會員輸 10 萬 × 50%       | 50,000（不同口徑，不可直接比大小） |

> 佔成範例用的是「單一會員輸 10 萬」；分桶範例用的是「全公司淨利 3 萬」。  
> 兩者**計算基礎不同**，表格僅供理解「算法長什麼樣」，不是同一場景的金額排名。

## 七、資料怎麼流？（SP 一覽）

### 分桶 v1

```text
summary_bet_records（僅 previous_day_type = 0）
    ↓ SP_summary_bet_record_by_agent
summary_bet_record_agents
    ↓ SP_calc_shareholder_winlose
summary_shareholder_winloses  →  shareholder_payout_logs（開期）
    ↓ SP_calc_shareholder_temp
summary_shareholder_temps
    ↓ SP_calc_shareholder
summary_shareholders
    ↓ SP_shareholder_payout
transaction_log_agents（type 5）＋ agents.balance
```

### 分桶 v2（2IN1，現行）

```text
summary_bet_records（僅 previous_day_type = 0）
    ↓ SP_summary_bet_record_by_agent
summary_bet_record_agents
    ↓ SP_calc_shareholder_winlose2
summary_shareholder_winloses  →  shareholder_payout_logs（開期）
    ↓ SP_calc_shareholder_temp2
summary_shareholder_temps
    ↓ SP_calc_shareholder2
summary_shareholders
    ↓ SP_shareholder_payout2
transaction_log_agents（type 5，投注分紅 + 業績分紅）＋ agents.balance
```

### 佔成

```text
summary_bet_records（僅 previous_day_type = 2）
    ↓ SP_calc_profit_share_winlose
summary_profit_share_winloses  →  profit_share_payout_logs（開期）

[選配] SP_calc_profit_share_event_cost / SP_calc_profit_share_payment_cost
    → 活動成本 / 支付成本分攤

    ↓ SP_calc_profit_share
summary_profit_shares

[系統外] profit_share_payout_logs status 3 → 4（後台／排程發佈）

    ↓ SP_payout_profit_share
TotalProfit ≥ 0 → transaction_log_agents（type 9）＋ agents.balance
TotalProfit < 0 → wallet_transaction_log_agents ＋ agent_wallets（佔成錢包）
```

| **`transaction_log_agents`** | ● | ● | 主錢包代理間轉帳 log | 分桶 **`type = 5`**；佔成賺 **`type = 9`**；`from_agent_id`＝總代、`to_agent_id`＝子代 |
| **`wallet_transaction_log_agents`** | — | ● | 佔成錢包帳變 | 僅 **`TotalProfit < 0`**；`wallet_type_id = 3` |
| **`agents.balance`** | ● | ● | 主錢包餘額 | 分桶與佔成「賺錢」派彩會更新總代／子代 balance |
