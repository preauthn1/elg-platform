驗證外部規範是否準確（防止憑訓練資料臆測）。

主題：$ARGUMENTS

---

## 做法

外部工具的規範（路徑、frontmatter 欄位、變數語法、觸發機制）常改版，憑訓練資料回答容易過時，所以每個結論都要有剛抓回來的官方原文撐著。

- 先把主題拆成具體的待驗證項目（例：「Codex skills 規範」拆成路徑、frontmatter 欄位、隱式觸發機制、顯式呼叫語法）。
- 每個項目用 WebSearch 找官方來源，優先順序：官方文件站、官方 GitHub repo 的 docs 目錄、官方 changelog；部落格與第三方教學只拿來交叉比對，不當主要來源。
- 用 WebFetch 抓原文，取出確切路徑／檔名、完整設定欄位、變數佔位符語法、觸發機制、範例代碼；全部項目合計至少 2 個官方來源已 WebFetch。
- 輸出下方對比表；認知有誤的項目，列出錯在哪、會影響哪些已寫的文件或設定、建議怎麼改。
- 官方來源查不到、或來源之間說法矛盾的項目，標「未驗證」並寫查了哪裡，不用推測語氣帶過。

| 項目 | 我原本的認知 | 官方最新規範 | 是否一致 | Source |
|---|---|---|---|---|
| ... | ... | ... | ✅／❌／未驗證 | [link] |

### 必附 Sources 段落

```markdown
Sources:

- [標題](URL)
```

---

## 禁止行為

- ❌ 跳過 WebFetch，憑記憶回答
- ❌ 只看一個來源就下定論
- ❌ 查不到官方來源的項目沒標「未驗證」就寫成結論
- ❌ 不附 Sources 直接列規範

## 完成判準

- [ ] 至少 2 個官方來源已 WebFetch
- [ ] 每個待驗證項目都有「我原本認知 / 官方最新 / 是否一致」三欄資料，並有官方來源；查不到官方來源的標「未驗證」並寫查了哪裡
- [ ] Sources 段落已附上
- [ ] 若發現錯誤，已列出下游影響與修正動作
