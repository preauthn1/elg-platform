# 在魔鏡建、改 pointer

這份文件給「操作手冊頁審過、要讓客服問得到」的時候讀。

## 什麼時候建

- 只替操作手冊頁建。客服從魔鏡拿到的答案要帶他到操作手冊，不是功能頁。
- 等頁面審過（頁首狀態是「已審」）再建。草稿頁建了 pointer，客服會讀到還沒確認的內容。

## pointer 的格式

照 `memory-store` skill 的三段結構：標題是問句、內文是答案、最後是出處。

```
新遊戲要怎麼上架？ / 遊戲商出了新遊戲前台看不到 / 怎麼把遊戲開給某個站台

新遊戲同步進系統後預設是關的，要在代理後台把遊戲管理、商戶遊戲管理、代理遊戲管理三層都打開，前台才看得到。完整步驟、什麼時候要開單、開單要附什麼，看 wiki 操作手冊「新遊戲上架與下架」：
http://0.0.0.0:3000/doc/5paw6ygk5oiy5lik5p626iih5lil5p62-4yYUu8KBKo
---
出處：wiki 操作手冊 › 遊戲 › 新遊戲上架與下架
```

- **標題**：客服代表提供的真實問法，至少三種，用「 / 」隔開。沒有客服提供的問法時，先問使用者，不要只用工程師的講法。
- **內文**：一兩句答案摘要，讓客服光看魔鏡回答就知道方向；接著寫頁名與完整網址。不要把整頁內容貼進來，正本在 wiki。
- **出處**：`wiki 操作手冊 › 本 › 頁名`。
- **tags**：`wiki-pointer`、`操作手冊`，加上模組名（例如 `遊戲商`）。
- **type**：`reference`。

## 建完要驗證

用三種不同的問法呼叫 `memory_search`，三種都要在前幾筆找到這筆 pointer。找不到就在標題補同義問法、在內文補同義詞，刪掉重存。

## 頁面改名或搬移時

wiki 的網址 id 不會變，但 pointer 裡的頁名與出處會過時。

1. 用頁名或網址搜 `memory_search`，找出所有指向這頁的 pointer。
2. 列給使用者看，確認要改哪幾筆。
3. 魔鏡的「更新」會留下舊版本，搜尋時可能兩版都出現，所以改內容一律刪掉舊的再存新的。刪除前一定要先得到使用者同意。
