# 功能開發說明文件：分類表與完整範例

這份文件給 `dev-toolkit:gitlab-release` 第 9 步叫起本 skill、要替主單決定放在「功能開發說明文件（待整合）」文件集哪個資料夾的時候讀。資料夾分兩層：大類 › 子類，文件放在子類底下。要增刪分類就開 MR 改本檔，不要在寫文件時自己新增。

## 分類表

大類資料夾的標題是「編號 大類」（例如「05 遊戲與遊戲商」），子類資料夾的標題就是子類名稱，不含編號（例如「遊戲商與商戶」）。

| 編號 | 大類 | 子類 |
|---|---|---|
| 01 | 會員 | 帳號與建立、認證與綁定、狀態與行為、遊戲帳號、VIP、報表 |
| 02 | 代理 | 帳號與組織、角色與權限、代理設置、審核與紀錄、代理模式、報表 |
| 03 | 金流 | 會員儲值（上分）、會員提現（洗分）、代理開洗分（對代理）、代理限額、調帳與流水、渠道與貨幣、報表 |
| 04 | 行銷活動 | 活動V2、舊版活動、刷新排行榜、打卡活動、新人專享挑戰、成長彩金、邀請好友、任務、綁定獎勵、禮碼與Coupon、報表 |
| 05 | 遊戲與遊戲商 | 遊戲商與商戶、遊戲與類別、維護、報表 |
| 06 | 風控 | 會員限制與追蹤、IP限制、遊戲商與遊戲限制 |
| 07 | 分潤與佔成 | 分桶股份（PS）、佔成設定、結算、報表 |
| 08 | 內容與通知 | 網站內容、訊息發送、客服、後台通知、報表 |

## 完整範例：target/tickets#4373

分類路徑「05 遊戲與遊戲商 › 遊戲商與商戶」，標題「遊戲商管理 > 商戶遊戲管理 - 查無資料時顯示遊戲商個性化設置狀態」。

```markdown
## 這次做了什麼

在「遊戲商管理 › 商戶遊戲管理」查某個遊戲商卻一筆遊戲都查不到時，頁面會在篩選區與清單之間多出一條滿版區塊，列出這個遊戲商在所選代理組別的個性化設置版位和各自的狀態。運營從這裡就能看出，清單是空的是因為版位被設成停用或敬請期待，不必再到個性化設置逐一翻找。

## 為什麼這樣做

- **四個條件都成立才出現**：組別有選、遊戲商有選、其餘四個篩選全空、查詢結果為 0 筆。填了遊戲名稱或代碼時，清單空掉可能是被條件濾掉的，這時顯示「停用」會給出錯誤的答案。
- **補充說明，不取代「暫無記錄」**：清單區照舊顯示「暫無記錄」，區塊只負責解釋原因。
- **每個版位列一列，並顯示版位名稱**：同一個遊戲商在同一組別可能有多個前台入口版位，狀態也可能不同，沒有版位名稱就分不出該去改哪一個。
- **由後端在查無資料時一併回傳版位**：不另外撈整個組別的版位清單，少打一次 API，前端也不用自己比對。

## 上線後的行為

- 組別與遊戲商都有選、其餘篩選全空、查詢結果為 0 筆時，篩選區與清單之間出現一條滿版區塊，標題是「此遊戲商在「<組別名稱>」的個性化設置狀態」；清單區仍顯示「暫無記錄」。
- 區塊內每個版位一列，欄位是廠商名稱（含 ID）、商戶名稱（含 ID）、版位名稱（含入口類型）、狀態。
- 狀態用標籤顯示：停用是紅色、啟用是綠色、敬請期待是橘色。
- 該遊戲商在這個組織有多個商戶時，商戶名稱用逗號分隔，已停用的商戶附註「（停用）」。
- 遊戲名稱、遊戲代碼、狀態、可否投注任一項有填時，查無資料也不出區塊，只顯示「暫無記錄」。
- 只選遊戲商、沒選組別時，不出區塊。
- 這個組別沒有建這個遊戲商的版位時，不出區塊，照舊顯示「暫無記錄」。
- 換頁換到超出範圍的頁碼時，不會誤出區塊，因為判斷依據是總筆數，不是當頁筆數。
- 查得到遊戲時正常顯示清單，不出區塊。
- 頁面其他元素不變：6 個篩選、清除與查詢、4 個批次按鈕、表頭 9 欄、分頁列。

## 影響範圍

- 平台：新代理後台
- 選單路徑：遊戲商管理 › 商戶遊戲管理
- 後端：API_Agent 的商戶遊戲清單查詢，在查無資料時多回傳版位資料（API_Agent commit `f581df187`）。API_Agent 必須比前端先上線；後端還是舊版時，區塊不會出現，也不會報錯。
- 語系：15 個語系檔各新增一個區塊標題的翻譯。

## 跟主單不一樣的地方

| 主單怎麼寫 | 實際怎麼做 |
|---|---|
| 資料來源 A 案或 B 案，待技術決定 | 採 B 案：後端在查無資料時附上版位資料，沒有新增 API |
| 狀態為「啟用」的情況不會發生，只會出現停用與敬請期待 | 啟用的版位也會列出。商戶底下沒有遊戲或商戶被停用時就會發生，顯示「啟用」比隱藏更能說明清單空掉另有原因 |
| 商戶名稱為一個商戶加 ID | 列出該遊戲商在本組織的全部商戶，多筆用逗號分隔，停用的附註「（停用）」 |
| 沒提到換頁 | 用總筆數判斷清單是否為空，換到超出範圍的頁碼不會誤出區塊 |

以上差異 MR 描述註明「已與 PM／開發確認」。

## 這次刻意不做與還沒做的

- 維護狀態：個性化設置沒有「維護」這個值，維護是「系統管理 › 遊戲商維護」的時間區間，屬於不同來源。
- 「去設定」的跳轉連結：區塊只顯示資訊。
- 通用的「查無資料原因」診斷：只處理個性化設置被關掉這一種情況。
- 既有欄位與篩選一個都不動：清單上的「狀態」是單一遊戲的開關，跟區塊裡的版位狀態是兩回事。
```
