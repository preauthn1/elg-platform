# 起訖日怎麼算

一句話版本：**只要問到開發什麼時候開始、什麼時候結束，其他三個日期都算得出來，不用一個一個問；算出來的日期一律避開台灣的國定假日與週末，使用者自己填的日期落在假日只提醒、不改。**

## 名詞速查

| 名詞 | 意思 |
|---|---|
| 起訖日 | 開始日與結束日，在 GitLab 上分別叫 `start_date` 與 `due_date` |
| 主單 | 需求本體那張單 |
| 開發子任務 | 從主單拆出來、給工程師寫程式的那張單 |
| 測試子任務 | 從主單拆出來、給測試人員驗收的那張單 |
| 工作日 | 照政府「行政機關辦公日曆表」要上班的日子；週末、國定假日、補假不算，補班日算 |
| 下一個工作日 | 某個日期之後（不含當天）的第一個工作日，用工具 `next_workday` 查 |
| 順延 | 主單結束日落在特定星期時，往後推到下週一以後的第一個工作日 |
| 預覽（PREVIEW） | 寫進 GitLab 之前先印出來給人看的完整內容 |

## 這份文件在整個流程的哪一步

- 問完開發起訖日之後，照這份文件把其餘日期算出來。
- 算出來的日期與依據要印在預覽裡。
- 使用者能決定的只有兩件事：開發的起訖日，以及測試結束日抓當天、下一個工作日或（大型系統類）自己指定。其餘日期一律照這份文件算，**不是建議值**，主單的日期不接受直接改成別的日子。
- 使用者改了開發起訖日或測試結束日的選擇，就照算法把其餘日期重算一次。
- 日期一律在建單當下就一起帶上，不要建完再補。建立工單的時候本來就吃得下開始日與結束日。

---

## 1. 四個日期怎麼來

| 哪張單 | 開始日 | 結束日 |
|---|---|---|
| 主單 | 跟開發子任務的開始日同一天 | 測試子任務結束日的**下一個工作日**，然後套第 2 節的順延規則 |
| 開發子任務 | 使用者指定，通常是開單當天 | 使用者指定 |
| 測試子任務 | **就是開發子任務的結束日**，因為開發做完才輪到測試 | **當天或下一個工作日**，看需求大小決定 |

算的順序固定是這樣：

1. 使用者給開發的開始日與結束日
2. 測試開始日 ＝ 開發結束日
3. 測試結束日 ＝ 當天，或開發結束日的下一個工作日
4. 主單結束日 ＝ 測試結束日的下一個工作日
5. 主單結束日如果落在週四到週日，就照第 2 節順延

「下一個工作日」一律用工具 `next_workday` 查，連假會整段跳過，例如 09-24 的下一個工作日是 09-29（跳過中秋節、週末與教師節）。不要自己加一天再判斷星期。

其他要注意的：

- 測試結束日**預設抓當天**；需求比較大才抓下一個工作日，而且要在預覽裡說明抓的是哪一種。
- **例外**：大型系統類的需求（多階段改造、跨服務重構）結束日由使用者自己評估後指定，**不套用「當天或下一個工作日」**。子任務模式選 `PHASED` 時一律走這個例外。
- 使用者只說「測試就是某天開始跟結束」這類話時，照字面設成同一天就好，不要再追問。
- **主單結束日不是照抄開發的結束日。** 先算出測試結束日，再取它的下一個工作日當主單結束日，留一個工作日緩衝。
- 有好幾張開發類子任務時（例如開發加前端）：
  - 預設共用同一組起訖，使用者可以逐張改。
  - 測試開始日取它要驗的那張開發子任務的結束日；成對的組合（例如 APIs開發 對 APIs測試、開發(Agent) 對 測試(Agent)、開發 對 測試(後端)、前端 對 測試(前端)）各自對應，對應不明時取所有開發子任務中最晚的結束日。
  - 主單開始日取最早的開發開始日，主單結束日取最晚的測試結束日的下一個工作日。

## 2. 主單結束日的順延規則

⚠️ **主單結束日落在週四、週五、週六、週日，一律順延到下週一以後的第一個工作日。**

換句話說：**主單結束日只能是週一、週二或週三的工作日。**

怎麼算：從這個日期起連續呼叫 `next_workday`，直到回傳的 `weekday` 是一、二或三，那一天就是順延後的主單結束日。不要自己加天數找週日或週一，連假時會算錯。

從第 1 節算出來的主單結束日是工作日，只會落在週四或週五；落在週六、週日的，是不建子任務時使用者自己填的結束日。

- 這條**只套用在主單的結束日**，開發與測試子任務的日期不動。
- 範例：測試在 10-07（週三）結束 → 下一個工作日是 10-08（週四）→ 週四要順延 → 10-08 的下一個工作日是 **10-12（週一）**（10-09 補假、10-10 國慶日、週末都跳過），落在週一，停。

## 3. 子任務的日期怎麼帶

- 除了 `PHASED` 以外的模式：子任務日期照第 1 節算出來，**不是整批照抄主單**。
- `PHASED`：每一期可以各自設結束日，不用跟主單一致。
- 不建子任務（`PARENT_ONLY`）：排期那一題改問主單的起訖日，可以不設；有結束日時同樣套第 2 節的順延規則。預覽的排期區塊只列一行主單。
- RD 自己做、不需要 QA 驗收（`RD_SELF`）：RD 給的開發起訖日就是主單起訖日，**不取下一個工作日、不套第 2 節的順延規則**。這種單沒有測試子任務，主單結束日就是 RD 預計完成的那一天。
- 使用者選「暫不設定」時：主單與全部子任務都不設日期，預覽標 `⚠ 無排期`。

**使用者自己填的日期落在放假日時，只提醒、不改。** 開發起訖日、`PHASED` 各期的日期、`RD_SELF` 的主單起訖日、`PARENT_ONLY` 的主單開始日，都是使用者自己填的（`PARENT_ONLY` 的主單結束日照第 2 節順延，順延結果一定是工作日）。這些日期用 `check_workdays` 查一次，是放假日就在預覽那一行後面標 `⚠ <日期> 是<假日名稱>`（週末沒有假日名稱，寫「週六」「週日」），例如 `⚠ 09-25 是中秋節`。可能是刻意安排加班，所以日期照使用者填的送出；使用者看到提醒後要改，就照新日期重算。

**使用者自己填的日期早於今天時，也只提醒、不改。** 今天的日期取 `check_workdays` 回傳的 `today_taipei`，不要自己看系統時間。早於今天的日期在預覽那一行後面標 `⚠ <日期> 早於今天`，例如 `⚠ 09-22 早於今天`；同一個日期又是放假日時，兩個提醒都寫。補開已經在做的單時，開始日本來就會早於今天，所以照使用者填的送出；這個提醒是讓打錯年份或月份的人看得出來。

## 4. 用工具查，不要自己推算

兩個工具都在工單小工具（`gitlab-workitem` server），唯讀，不需要 GitLab 金鑰：

| 工具 | 用途 | 回傳裡要用的欄位 |
|---|---|---|
| `mcp__plugin_gitlab-mcp_gitlab-workitem__next_workday` | 查某個日期的下一個工作日 | `next_workday`、`weekday`，跳過的放假日在 `skipped` |
| `mcp__plugin_gitlab-mcp_gitlab-workitem__check_workdays` | 查使用者填的日期是不是工作日，順便拿到星期 | 每個日期的 `is_workday`、`weekday`、`note`（假日名稱），以及 `today_taipei`（判斷日期是否早於今天用） |

- 預覽裡每個日期後面的星期，一律取自工具回傳的 `weekday`。
- 工具回錯誤（日曆還沒收錄那一年）時，不要自己推算：預覽的排期區塊寫出錯誤原文並標 `✗ 排期算不出來`，算進「擋下的項目」。使用者可以改成「暫不設定」先開單。
- 回傳的 `warnings` 不是空的（政府出了修正版或新年度、repo 還沒跟上）時，照常用回傳結果，並把 warnings 原文列在排期區塊下方。

## 5. 預覽要長什麼樣

```
排期（照固定規則推算）：
  開發子任務：2026-09-18(五) ~ 2026-09-22(二)   （你指定的）
  測試子任務：2026-09-22(二) ~ 2026-09-22(二)   （開始日＝開發結束日；結束日抓當天，需求規模一般）
  主單      ：2026-09-18(五) ~ 2026-09-23(三)   （結束日＝測試結束日的下一個工作日＝09-23(三)，不用順延）
```

有好幾張開發類子任務時，共用同一組起訖就列一行，括號寫出是哪幾張共用；使用者逐張改過日期，就每張各列一行，行首寫子任務後綴：

```
  開發子任務：2026-09-22(二) ~ 2026-09-24(四)   （你指定的；開發、前端兩張共用）
```

```
  開發子任務（ - 開發）：2026-09-22(二) ~ 2026-09-24(四)   （你指定的）
  開發子任務（ - 前端）：2026-09-23(三) ~ 2026-09-25(五)   （你指定的）⚠ 09-25 是中秋節
```

中間有放假日被跳過時，寫出跳過了哪些。主單與測試子任務（抓下一個工作日時）都要寫，否則讀的人看不懂為什麼差了好幾天：

```
  測試子任務：2026-09-24(四) ~ 2026-09-29(二)   （開始日＝開發結束日；結束日抓下一個工作日，跳過 09-25 中秋節、週末、09-28 教師節）
  主單      ：2026-09-22(二) ~ 2026-09-29(二)   （結束日＝測試結束日 09-24(四) 的下一個工作日，跳過 09-25 中秋節、週末、09-28 教師節）
```

有順延的時候，要把原本算出來的日期跟順延後的日期兩個都寫出來：

```
  主單      ：2026-10-05(一) ~ 2026-10-12(一)   （結束日＝測試結束日的下一個工作日＝10-08(四)，週四要順延，改成 10-12(一)）
```

使用者填的日期落在放假日時：

```
  開發子任務：2026-09-24(四) ~ 2026-09-25(五)   （你指定的）⚠ 09-25 是中秋節
  主單      ：2026-09-24(四) ~ 2026-09-25(五)   （你指定的，不順延）⚠ 09-25 是中秋節      ← RD 自己做的單
```

不拆子任務時，使用者填的結束日落在放假日又要順延，把假日名稱寫進順延說明，不另標 ⚠：

```
  主單      ：2026-10-01(四) ~ 2026-10-12(一)   （開始日是你指定的；結束日你填 10-10(六，國慶日)，要順延，改成 10-12(一)）
```

工具回錯誤時，算得出來的日期照印，算不出來的標 `✗`，最後一行寫錯誤原文與處理方式；這一項算進「擋下的項目」：

```
  開發子任務：2027-12-28(二) ~ 2027-12-30(四)   （你指定的）
  測試子任務：2027-12-30(四) ~ ✗
  主單      ：2027-12-28(二) ~ ✗
  ✗ 排期算不出來：<錯誤原文>。日曆要由 GFF-Marketplace 的維護者更新；要先開單可以把排期改成「暫不設定」
```
