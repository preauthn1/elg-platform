# 工單標題怎麼寫

一句話版本：**標題要先過第一關的整體格式，再看主題有沒有寫成「模組 > 頁面 - 描述 - 表單項次」。**

## 名詞速查

| 名詞 | 意思 |
|---|---|
| 主單 | 需求本體那張單，標題以 `[GFF]` 開頭 |
| 子任務 | 從主單拆出來的工作單，例如「開發」「測試」各一張 |
| 站別標記 | 標題裡的 `[TPower]`、`[ME77]` 這種方括號，代表這張單是哪個站台的 |
| 主題 | 標題去掉 `[GFF]` 與站別標記之後，剩下的那一段文字 |
| 表單項次 | 「新版後台回報」Google 表單上的第幾項，一個數字 |
| 正規表示式（regex） | 一串用來檢查文字格式對不對的規則 |
| 預覽（PREVIEW） | 寫進 GitLab 之前先印出來給人看的完整內容 |

## 主單標題規則

標題分兩關檢查，**第一關過了才檢查第二關**。

### 第一關：整體格式

格式：`[GFF][<站名>]<主題>`

- `[GFF]` 永遠要有。這是業務組固定的開頭，少了這三個字團隊會找不到單。
- `<站名>` 必須是合法的站台代號，清單見下方白名單。要不要掛見「站別標記要不要掛」。
- 所有站台共用的功能（APIs、基礎建設）不掛站別，直接寫 `[GFF]<主題>`。
- 內部工具的單把工具名稱放在站別的位置，寫成 `[GFF][Olympus]<主題>` 或 `[GFF][GM]<主題>`（GM 是 GFF-Marketplace）。
- 整個標題上限 100 字。

### 第二關：主題本身的格式

主題要寫成：`模組 > 頁面 - 描述 - 表單項次`

- **模組階層用 ` > ` 串起來**，大於符號前後各留一個半形空格，例如 `會員管理 > 帳號管理`。
- 接著用 ` - ` 加一句描述，講這張單要做什麼。
- 尾巴的 ` - <數字>` 是表單項次，**只有來自「新版後台回報」Google 表單的單才加**。
  - **數字要對回表單上的實際項次，不可以憑口頭講的就填。**

範例：`[GFF]會員管理 > 帳號管理 - 新增匯出按鈕 - 12`

**第二關是判斷，不是一律擋下來。**

- 後台回報與功能需求（C 類）本來就有模組跟頁面，套得進這個格式。
- 廠商接入類（A 金流商、B 遊戲商、Bp 簡訊）沒有模組頁面的階層，套不進去是正常的，例如 `[GFF][TP]joker baccarat 單錢包(直對)接入`。

所以分三種情況處理：

| 判斷結果 | 要做什麼 |
|---|---|
| 符合 `模組 > 頁面 - 描述` | 照用 |
| 不符合，而且分類是 A、B、Bp（廠商接入） | 照用，不提示 |
| 不符合，而且是內部工具的單（Olympus、GM） | 照用，不提示。內部工具沒有「模組 > 頁面」這層結構 |
| 不符合，而且分類是 C 或 D | 在預覽標 `⚠ 主題未套用「模組 > 頁面 - 描述」格式`，請使用者確認或修正 |

**三種情況都不要自行改寫主題的用字。**

**使用者講的是一整句話、不是一個短標題時**，主題只取說明「要做什麼」的那一段，用字照原文不改；補充說明移到內文，不丟掉。預覽的標題那一行加註「標題從你的訊息擷取」，請使用者確認。

- 那一段開頭的站台或工具名稱已經放進站別標記時，從主題拿掉，免得標題出現兩次。緊跟在名稱後面的「的」與空格一起拿掉，其餘用字不改。
- 補充說明放哪一段：範圍寫進「作法」的需求說明；「不動 X」寫進「不在本單範圍」，並寫出要找誰或往哪做；原因寫進「緣由」。

| 訊息 | 主題 | 移進內文的 |
|---|---|---|
| 「pm-ticket-create 的排期要能避開台灣國定假日，只改 skill 文件」 | `pm-ticket-create 的排期要能避開台灣國定假日` | 「只改 skill 文件」寫進作法 |
| 「Olympus 的會員查詢頁要加一個依手機號碼搜尋的欄位」 | `會員查詢頁要加一個依手機號碼搜尋的欄位`（完整標題 `[GFF][Olympus]會員查詢頁要加一個依手機號碼搜尋的欄位`） | 無 |
| 「TPower 後台的會員列表載入太慢要優化，只動列表頁，匯出功能不動」 | `後台的會員列表載入太慢要優化`（完整標題 `[GFF][TPower]後台的會員列表載入太慢要優化`） | 「只動列表頁」寫進作法；「匯出功能不動」寫進不在本單範圍。「載入太慢」是現象，不是「不做會怎樣」，緣由照樣要問 |

### 站點縮寫與 Slack 頻道（2026-10-22 定案）

新開的單討論特定站點時，站別標記一律用下表的縮寫（全大寫）。同一張表也決定開單後要到哪個 Slack 頻道通知開發，見 `slack-notify.md`。

| 討論的站點 | 站別標記 | Slack 頻道 |
|---|---|---|
| t-power | `[TP]` | `#gff-tpower站` |
| vworld | `[VWMY]` | `#gff-vworld` |
| vworldsg | `[VWSG]` | `#gff-vworldsg` |
| wintoto | `[WTT]` | `#gff-wintoto` |
| yes2win | `[Y2W]` | `#gff-yes2win站` |
| me77 | `[ME77]` | `#gff-me77-vwb2c` |
| togo | `[VWMY]`，內文開頭註明站點是 togo | `#gff-vworld` |
| 77bet | `[VWMY]`，內文開頭註明站點是 77bet | `#gff-vworld` |
| hero9 | `[HERO9]` | `#ttn-工作群` |
| TTN 專案的單 | `[TTN]` | `#ttn-工作群` |
| 各站共用（共同區塊） | 不掛，只寫 `[GFF]` | `#gff-general` |

白名單裡其他寫法（`TPower`、`VWorld`、`YES2WIN` 等）是舊單用過的，留著讓舊標題照樣通過檢查；新開的單照上表寫。

### 站別標記要不要掛

⚠️ **來自 Google 回報表單的單子，不掛站別標記。** 這是團隊慣例，原因是：

- 那份表單是所有站台共用的，ME77、TPOWERCS30、YSP07 這些站都往裡面丟。
- 掛上 `[TTN]` 會把一個跨站的問題誤標成單一站台的問題。
- 表單來源的標題就是 `[GFF]模組 > 頁面 - 描述 - 項次`。

反過來說：

- **PM 自己提的需求（不是從表單來的）仍然要掛站別。**
- 判斷依據是**「這張單是不是從表單項次來的」**，不是看內容在講什麼。

最後一條：**不要把標題寫成需求說明**，需求說明放在工單內文。

## 機器可讀 schema

```yaml
# 第一關：整體格式
title_regex: "^\\[GFF\\](\\[(<station>)\\])?<topic>$"

# 第二關：<topic> 的內部格式（模組階層 > 頁面 - 描述 - 表單項次）
topic_format: "<模組>[ > <子模組>...] - <描述>[ - <表單項次>]"
topic_format_enforcement:
  C: warn      # 功能優化／修復：不符合就在預覽提示，請使用者確認
  D: warn      # 系統維護
  A: skip      # 金流商接入：沒有模組頁面階層，不檢查
  B: skip      # 遊戲商接入
  Bp: skip     # 簡訊／OTP
topic_format_skip_stations: [Olympus, GM]   # 內部工具的單不論分類都不檢查
topic_rules:
  hierarchy_separator: " > "     # 前後各一個半形空格
  description_separator: " - "
  form_item_suffix:
    applies_when: "來源是「新版後台回報」Google 表單"
    value: "表單的實際項次數字，不可憑口述套用"
    otherwise: "整段省略"

# 站別標記是否要掛
station_tag_rule:
  from_google_form: false   # 表單來源不掛站別（表單為全站共用）
  pm_originated: true       # PM 自提需求要掛站別
  decided_by: "這張單是不是從表單項次來的，不是看內容"

station_whitelist:
  # 主流站台 token (依 #3081 / Leah 慣例)
  - TPower
  - TP          # TPower 縮寫 (Leah 常用，例 #3081)
  - ME77
  - Me77        # 大小寫變體
  - Alfawin77
  - VWorld
  - VW
  - VWSG
  - Yes2win
  - YES2WIN     # 全大寫變體 (例 #3083)
  - Wintoto
  - TTN         # TTN 項目
  - VWMY        # VWorld 馬來
  - VW2         # target/tickets 有同名里程碑「VW2」
  - WTT         # Wintoto 的縮寫
  # 內部工具（不是站台，放在站別標記的位置）
  - Olympus
  - GM          # GFF-Marketplace（Claude Code 的 skill 市集）
  - Y2W         # Yes2win 的縮寫
  - HERO9       # hero9 站（Slack 頻道在 #ttn-工作群）
  - APIs        # 跨站基礎建設

topic_verbs:
  # 主題第一個動詞建議用以下之一
  - 配置
  - 接入
  - 優化
  - 修復
  - 新增
  - 重構
  - 維護
  - 升級
  - 切換
  - 同步

length_limit: 100
```

## 子任務標題規則

格式：`<主單標題去掉尾端表單項次> - <後綴>`

- 複製主單標題，**但要把尾端的 ` - <表單項次>` 去掉**。項次是回報表單的索引，對子任務沒有意義。
- 後面接 ` - ` 加角色後綴，分隔線前後各一個半形空格，例如 ` - 開發`、` - 測試`。
- 後綴有哪些見 `subtask-patterns.md`。
- 範例：
  - 主單：`[GFF]會員管理 > 帳號管理 - 新增匯出按鈕 - 12`
  - 子任務：`[GFF]會員管理 > 帳號管理 - 新增匯出按鈕 - 開發`

⚠️ **`PHASED` 模式是例外**（2026-09-02 起）：

- 子任務標題**不帶 `[GFF]` 開頭**，也不複製主單標題。
- 格式是 `<主題> 第<N>期：<期別主題>`，期別一律用中文，例如 `多幣別錢包 第零期：契約凍結與寫入者歸屬`。
- 細節見 `subtask-patterns.md` 的 `PHASED` 段。

## skill 建單前要做的檢查

1. **第一關**：對標題跑 `title_regex` 檢查。不通過就提示使用者修正。
2. 確認站台代號在白名單裡。不在就提示使用者，請他補白名單或改代號。
3. 確認站別標記該不該掛：來源是 Google 回報表單就不掛，PM 自己提的需求就要掛。
4. **第二關**：檢查主題是否符合 `模組 > 頁面 - 描述 - 表單項次`。不通過就提示使用者修正。
5. 有表單項次的話，確認數字對得回表單上的實際項次，**不可以憑口頭講的就填**。
6. 確認整個標題不超過 100 字。超過就請使用者自己縮短，不要自行截短或改字。
7. **不要主動「優化」標題用字**，例如把「接入」改成「整合」。動詞怎麼選是業務慣例。
