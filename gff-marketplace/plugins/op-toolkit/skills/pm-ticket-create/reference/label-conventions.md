# 標籤怎麼掛

一句話版本：**主單掛「不收費」，子任務都有負責人時再掛「分配QA」「分配開發」，否則掛「未分配」；子任務只掛自己那個角色的標籤，優先級與計費標籤都不往下傳。**

## 名詞速查

| 名詞 | 意思 |
|---|---|
| 標籤（label） | GitLab 工單上的彩色小標，用來標狀態、優先級、計費 |
| 主單 | 需求本體那張單，建在 `target/tickets` |
| 子任務 | 從主單拆出來的工作單，建在 `target/ticket_tasks` |
| 階段標籤 | `0. 分配QA`、`0. 分配開發` 這類，代表這張單走到哪一步 |
| 計費標籤 | `0.0不收費`、`0.0需收費`、`0.0已報價`，代表這個需求跟客戶收不收錢 |
| 優先級標籤 | `0.2 優先`、`0.2 不可延期`、`0.2 插單` |
| 同步標籤 | `0.1 待同步APIs` 這類，代表這個需求還要同步到別的系統 |
| 預覽（PREVIEW） | 寫進 GitLab 之前先印出來給人看的完整內容 |
| skill 自動掛 | skill 會主動掛上去，不用人開口 |

> 這份文件對應 `target/tickets` 與 `target/ticket_tasks` 上實際存在的標籤結構。
> skill 載入這份文件時，**以 `mapping` 區的 YAML 為準**。

---

## mapping (機器可讀)

```yaml
# Parent (target/tickets) labels
parent_labels:
  phase:
    type: multi    # 分配階段是「0. 分配QA」＋「0. 分配開發」兩個並掛
    progression: [unassigned, assigned, qa_review, pm_review]   # 先測試驗收，再 PM 確認
    autofill_by_skill: true
    rule: |
      子任務同一輪建好、而且每一張都有負責人 → assigned，掛子任務實際涵蓋的派工標籤
      （有開發類子任務掛 0. 分配開發，有測試類子任務掛 0. 分配QA）。
      不拆子任務（PARENT_ONLY），或有任何一張子任務待認領 → unassigned。
      RD 自己做、不需要 QA 驗收（RD_SELF）→ 只掛 0. 分配開發（主單已指派給開單的 RD）。
    values:
      unassigned: "0. 未分配"
      assigned:   ["0. 分配QA", "0. 分配開發"]
      qa_review:  "0. TEST驗收"
      pm_review:  "0. PM確認"
  billing:
    type: single
    autofill_by_skill: true    # 主動掛「0.0不收費」，不留給 PM 後補
    default: "0.0不收費"
    values:
      free:     "0.0不收費"
      charged:  "0.0需收費"
      quoted:   "0.0已報價"
  priority:
    type: single
    autofill_by_skill: true   # 依 Q3_priority 決定
    values:
      normal:   null   # 一般 = 不掛 label
      priority: "0.2 優先"
      no_delay: "0.2 不可延期"
      insert:   "0.2 插單"
  sync:
    type: multi      # 可同時掛多個
    autofill_by_skill: false   # 由 PM 決定，skill 不主動
    values:
      apis: "0.1 待同步APIs"
      tp:   "0.1 待同步tp"
      vw:   "0.1 待同步vw"

# Subtask (target/ticket_tasks) labels
subtask_labels:
  phase:
    type: single
    autofill_by_skill: true   # 依 subtask role 決定
    values:
      dev_assigned: "0. 分配開發"   # " - 開發" / " - 前端" 類子任務（含 " - 開發(XXX)"）
      qa_assigned:  "0. 分配QA"     # " - 測試" 類子任務（含 " - 測試(XXX)"）
  priority:
    autofill_by_skill: false  # 不繼承主單的 0.2 *
  billing:
    autofill_by_skill: false  # 不繼承主單的 0.0 *
```

## 建主單的時候掛什麼

**一般情況主單掛三個：`0. 分配QA` ＋ `0. 分配開發` ＋ `0.0不收費`。**

1. **階段標籤** → 看子任務的派工狀況：
   - 子任務同一輪建好、而且每一張都有負責人 → 掛 `0. 分配QA` 加 `0. 分配開發`，主單直接進入「已分配」狀態。只有開發類子任務時（例如 `PHASED`）只掛 `0. 分配開發`。
   - 子任務模式選 `PARENT_ONLY`（不建子任務），或有任何一張子任務待認領 → 掛 `0. 未分配`。
   - RD 自己做、不需要 QA 驗收（`RD_SELF`）→ 只掛 `0. 分配開發`。主單已經指派給開單的 RD，不掛 `0. 分配QA`，QA 才不會誤以為要驗收。
2. **優先級標籤** → 依使用者選的優先級掛對應的 `0.2 *`。選「一般」就不掛。
3. **計費標籤** → **主動掛 `0.0不收費`**，不留給 PM 後補。
   - 實際上是「需收費」或「已報價」時，由使用者在預覽之前講明，skill 才改掛對應的標籤。
4. **同步標籤** → **不掛**。`0.1 待同步*`（「0.1 待同步」開頭的標籤）由 PM 決定，預覽裡列在「PM 接手後要補」。

## 建子任務的時候掛什麼

1. **階段標籤** → 看這張子任務是什麼角色：
   - ` - 開發`、` - 前端`、` - XXX開發`、` - 開發(XXX)`、` - 前端(XXX)` → 掛 `0. 分配開發`
   - ` - 測試`、` - XXX測試`、` - 測試(XXX)` → 掛 `0. 分配QA`
2. **優先級標籤與計費標籤** → 都不掛，只有主單才有。

## 主單後續的狀態怎麼流轉

這一段只是給人參考，**建新單時 skill 不會主動去改**：

- `0. 未分配` → 子任務都有負責人之後，換成 `0. 分配QA` 加 `0. 分配開發`（補拆子任務時由 skill 在預覽列出、PM 同意後改）
- 開發做完、進入測試 → 換成 `0. TEST驗收`
- 測試通過、PM 最後確認 → 換成 `0. PM確認`

## 建單前要檢查標籤存在

建單之前一定要確認要掛的標籤在目標專案裡真的存在。原因是：

- 建立工單時可以直接用標籤的**名稱**，不需要標籤的編號。
- 但那個標籤必須已經存在於該專案，否則 GitLab 會回 422 錯誤，整張單建不起來。

怎麼查：

- 主單專案：每個要用的標籤各查一次 `mcp__plugin_gitlab-mcp_gitlab__list_labels`（`project_id=<parent_id>`, `search=<標籤名稱>`）
- 子任務專案：同上，`project_id=<subtask_id>`

回傳裡有名稱完全相同的那一筆，才算標籤存在；`search` 是部分比對，會連名稱相近的標籤一起回傳。不要一次撈整頁再比對：一頁最多 100 筆，主單專案的標籤已經接近 100 個，超過後排在後面的標籤會被誤判成不存在。**缺標籤就提示使用者，不要自動建一個新的**，因為標籤名稱是團隊約定俗成的，不該由 skill 自行增加。

## 紅線

- 🚫 **不要在主單同時掛 `0. 未分配` 跟 `0. 分配開發`**，這兩個互相矛盾。
- 🚫 **子任務都有負責人時不要掛 `0. 未分配`**，狀態就是已分配；有任何一張待認領時才掛。
- 🚫 **子任務不要跟著掛 `0.2 *` 與 `0.0 *`**，優先級與計費標籤只掛在主單。
- ✅ **主單一律掛 `0.0不收費`**；子任務都有負責人時再加 `0. 分配QA`、`0. 分配開發`。
- ✅ **可以同時掛多個 `0.1 待同步*`**，一個需求要同步到好幾個系統時會用到。
