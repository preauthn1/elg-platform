# 截圖視覺解析指南（Mode B）

> 給維運 / 客服貼 N 張 TG 截圖時，AI 如何分類並萃取每張的內容。
> 截圖內容**完全**透過視覺模型（multimodal LLM）解讀；本檔說明截圖分類與每類要記下的欄位。

---

## 1. 截圖五大類型

每張截圖先判斷屬於下面哪一類，再照該類的萃取目標記下內容：

### 1.1 TG 對話截圖
**萃取目標**：
- `tg_group`（群組名）— 通常在截圖頂部，client 沒貼到頂部時取自 user 直接告知
- 發言者角色：客服（內部）/ 站方（外部白標）/ 玩家轉述
- 發言時間（時分）
- 訴求關鍵句
- 玩家 ID / 訂單號（若對話中提及）

### 1.2 後台畫面截圖
**萃取目標**：
- 玩家 ID（通常在會員一欄）
- 訂單號（單號 / order_no 欄）
- 金額、狀態、時間欄
- 後台 logo / 標題識別 station

### 1.3 玩家投訴文字截圖
**萃取目標**：
- 玩家原話（用於 `symptom` / `expected`）
- 玩家 ID / 暱稱

### 1.4 遊戲畫面 / 錯誤彈窗
**萃取目標**：
- 遊戲商名稱（vendor）
- error code / error message
- 觸發時點

### 1.5 其他
**包括**：
- Email 截圖
- 系統 log 截圖（含 stack trace）
- Excel 報表截圖
- 不確定類型

**萃取目標**：
- 標 `需手動釐清`
- 列出畫面上可辨識的關鍵字

---

## 2. 每張截圖要記下的東西

每張截圖依「截圖五大類型」一節的分類，記下看得到的：群組名、發言者與角色（客服、站方、玩家）、時間、站台線索（logo、網址）、遊戲商線索、玩家 ID、訂單號、金額（含幣別）、錯誤碼，以及對話的逐字內容。看不清楚的欄位記為「無法辨識」，「模糊截圖的處理」一節會拿它提示使用者。

**規則**：
- 看不清楚的欄位不要編造，記為「無法辨識」。
- 玩家敏感資料（手機、真名）→ 原樣輸出，由後續整合層決定如何處理
- 對話 transcript 保留原語言（簡中 / 繁中 / 英文）

---

## 3. 整合策略（多張截圖）

每張截圖都記完之後，照下表合併：

| 欄位 | 合併規則 |
|---|---|
| `tg_group` | 取出現的第一個非空值；若多張不一致 → AskUserQuestion 釐清 |
| `tg_contact` | 取 TG 對話截圖中**客服**身分的發言者 |
| `station` | 多張共識；衝突 → AskUserQuestion |
| `vendor` | 取**所有**提及的（可能多遊戲商） |
| `player_id` | 取共識；多玩家 → 列出全部，AskUserQuestion 釐清是「同一案」還是「多案合併」 |
| `order_no` | 同上 |
| `time_range` | 取最早 ~ 最晚 |
| `symptom` | 由 AI 跨截圖綜合一句話（**不要逐字拼接**） |
| `expected` | 由 AI 從玩家 / 客服訴求綜合 |
| `transcript` | 按時間順序拼接放入 description 收摺區 |

---

## 4. 截圖簡述生成（用於 description 附件清單）

每張截圖在 description 中以單行簡述呈現：

```
- 截圖 N：<類型>，<最關鍵的 1 句說明>
```

範例：
- `截圖 1：TG 對話，yuusei 於 5/22 06:13 反饋 heng118928 充值 100 未領活動獎勵`
- `截圖 2：後台訂單畫面，顯示玩家充值 100 扣手續費 7.5 實收 92.5`
- `截圖 3：玩家投訴，heng118928 抱怨「為什麼沒拿到獎勵」`

避免：
- ❌ `截圖 1：一張圖片` （無資訊量）
- ❌ `截圖 1：客戶反饋的截圖` （太泛）
- ❌ 全部用相同描述

---

## 5. 模糊截圖的處理

有欄位記為無法辨識時：

1. 在預覽顯示 `⚠️ 截圖 N 模糊：<列出>`
2. 詢問 user 是否要：
   - 補充更清晰的截圖
   - 用文字補充該欄位
   - 接受模糊並建單（標 `需手動釐清`）

不要為了完成建單而**編造**模糊欄位的內容。

---

## 6. 視覺解析的成本意識

- 請使用者一次貼完所有截圖再開始整理，同一批圖不要重複解析。
