# 考古分流：分類判準與 archive 檔規格

先過主檔「個別記憶檔的考古分流」節的成本閘門（檔案 ≥ 5,000 字元且可搬 ≥ 2,000 字元）才進本檔。archive 有約 800 字元的固定成本，且分類本身有錯搬風險，小檔不值得專程做。

## 分類判準

分兩類，**搬錯的代價不對稱**：

| 類別 | 特徵 | 處置 |
|---|---|---|
| **A＝防翻回護欄** | 記的是「曾據 X 推出錯誤結論」（⛔已推翻／別再撿／勿誤判） | 🔴 **完整留在主檔**。它形式上是歷史、功能上是**當前約束**，搬走＝攔截失效 |
| **B＝純考古** | 「當時怎麼查的、查到多少、逐輪修了什麼」：鑑識時間線、覆蓋率快照、逐 commit 明細 | 分流到 `archive_*.md` |

**邊界案例從嚴**：一段落若內嵌未在他處重述的操作性約束，整段留主檔，或先把約束抽出來再搬。

## archive 檔規格

- 命名 `archive_<主題>.md`，與來源主檔 **1:1**（不開全域大雜燴）
- frontmatter `type` 沿用來源檔
- **不進 MEMORY.md 索引**
- 主檔尾部一行 📦 wikilink 指向 archive、archive 導言反指主檔（雙向；`check.py` 會驗配對）
- description 註明「考古用，不進 MEMORY.md 索引；當前結論在 <主檔>」
