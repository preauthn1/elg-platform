# Memory 查詢策略（魔鏡）：先分流 列舉 vs 單筆

從共享記憶（魔鏡）查東西，**先分流**：

- **單筆 recall**（「魔鏡你知道 X 嗎」「問魔鏡 X」「X 是什麼／多少／在哪」）→ 直接 `memory_search` 語意查一筆即可，**不套下面的列舉 SOP**；查到就答、查不到就明說沒有。別因為它不是「有哪些」、或「沒有專門 skill」就略過不查魔鏡——用戶提到魔鏡就是要你查共享記憶。
- **列舉型**（「有哪些 XX」「XX 清單」「全部 XX」）→ 走本文列舉 SOP：**用 `memory_list` 帶 tag 做確定性列舉**，不要用 `memory_search` 的語意 top-k 硬撈——top-k 會漏項，而且你不會知道漏了。

## 為什麼不能只靠 memory_search

| 工具 | 本質 | 對清單型查詢 |
|---|---|---|
| `memory_search` | 語意相似度排序，回傳前 K 筆（top-k） | ❌ 只保證「跟查詢字串相似」，不保證「涵蓋整類」，會漏掉簡稱／別名／語意較遠／共用資料的項目，且回傳不會告訴你漏了 |
| `memory_list(tags=[...])` | 依 tag 分類列舉，回傳該 tag 下**全部**記錄（分頁） | ✅ 用 `has_more` / `total_pages` 可確認是否撈完，不受 top-k 影響 |

**典型翻車**：對「有哪些 X」跑 `memory_search(limit=5)` 一兩次，把結果拼一拼當全集——抓到幾筆就當全部，漏項且無感。清單型查詢要改用 `memory_list` 帶 tag。

## 觸發時機

以下語意都算「清單／列舉型查詢」，應套用本策略：

- 「XX 清單 / XX 列表」
- 「有哪些 XX」「所有 XX」「全部 XX」
- 「查一下 XX 分類底下的資料」
- 隱含要彙整多筆同分類記錄的問題（例如「幫我整理一下我們所有的 XX」）

**單筆 recall 不走本 SOP**（例如「A 的聯絡窗口是誰」「魔鏡你知道 X 嗎」）——見開頭分流，直接 `memory_search` 查一筆即可（仍要查，別略過）。

## 查詢流程 SOP

### 1. 確定性列舉：`memory_list` 帶 tag

先鎖定這個分類對應的 tag（通常就是分類名稱本身）。不確定 tag 時，先 `memory_list()` 瀏覽、或 `memory_search` 定位到一筆該類記憶，看它的 `tags`。

```
memory_list(tags=["<分類tag>"], page_size=100)
```

- **務必檢查 `has_more` / `total_pages`**：`has_more:false` 才代表撈完；超過 100 筆會分頁，要 `page += 1` 逐頁撈到完整集合，不要看第一頁就收手。
- 分類由多個 tag 交集定義時，用 `tag_match:"all"` 取交集。

這一步拿到的就是**完整集合**，不需要靠語意搜尋去猜有哪些。

### 2. 交叉核對：清單／導航記憶當期望值

若該分類有「清單／導航記憶」（tag 含 `清單` 或 `導航`，memory-store 批次寫入時自動生成），它會宣稱「共 N 筆、分別是誰」。拿它跟 step 1 實際列舉筆數 M 交叉核對：

- **M == N** → 完整，可出結果。
- **M != N** → 名冊漂移（registry drift）：可能是清單記憶沒同步、或有記憶漏貼 tag。**明講差在哪**，別當沒事。
- 清單記憶內文常帶特例備註（例：「XX 沒有獨立記錄，要去 YY 查，兩者共用資料」）——這種備註往往能提前解釋「為什麼某項查不到獨立記錄」，不要略過。

### 3. 補細節才用 `memory_search`，且逐項查

需要每一項的細節時，照 step 1 的名單**逐項各查一次**；不要把多個主體塞進同一句 query（會稀釋語意相似度、排序不穩）。

```
❌ memory_search(query="A B C D 的聯絡窗口")
✅ memory_search(query="A 的聯絡窗口")
   memory_search(query="B 的聯絡窗口")
   ...
```

### 4. 彙整前核對數量，主動報缺漏

出結果前，回頭比對「應有幾筆」與「自己實際彙整出幾筆」：

- 一致 → 出彙整結果。
- 不一致 → **明確告訴用戶少了哪一項、以及原因**（沒查到 / 該項本來就沒有獨立記錄 / 要另外去哪裡查），不要悄悄跳過不提。

## 常見錯誤（反面示範）

- 用 `memory_search(limit=5)` 跑兩三次、把結果拼起來當全集 → top-k 會漏，且你不會察覺。
- `memory_list` 只看第一頁就收手，沒檢查 `has_more`。
- 清單記憶宣稱 N 筆，實際只湊到 M 筆卻不回報差異。

## 對話範例（冷啟）

**用戶問**：「幫我整理一下我們所有的供應商」

正確做法：

1. `memory_list(tags=["供應商"], page_size=100)` → `total:12, has_more:false`，一次拿到完整 12 筆名單（確定性，不靠語意猜）。
2. `memory_search(query="供應商清單")` 找到導航記憶宣稱「共 12 家」→ 與 step 1 的 12 筆一致 → 確認完整。
3. （某家要細節時）逐家 `memory_search(query="○○ 供應商 聯絡窗口")`。
4. 彙整 12 家輸出。若導航記憶說 13 家、但列舉只有 12 筆，主動指出「少了哪一家、需去哪裡查」，不悄悄跳過。

錯誤做法：直接 `memory_search(query="所有供應商", limit=5)`，抓到 5 筆就當全部——漏掉 7 家且完全無感。

## 工具對照

| 用途 | 工具 |
|---|---|
| 確定性列舉一整類（清單型查詢主力） | `memory_list`（帶 `tags` / `tag_match` / `page` / `page_size`） |
| 單項語意查詢、補細節 | `memory_search` |
