## ✍️ 寫入資料（教魔鏡一件事）

核心心法一句話：**用「別人會怎麼問」的方式來寫。**

用三段式模板：

```
[標題：用戶會問的問句，多個問法用 / 隔開]

[內文：把答案講清楚，口語化，保留原始細節與具體數字]
---
出處：文件名 / 分享者
```

**範例：**

```
Playtech 的返利要選哪個選項？ / PT 返利設定在哪 / playtech 佔成怎麼設

代理模式管理 > 三層代理 > 投注佔成設定 —— 選「Playtech SW」。
---
出處：Chelsea 的筆記：後台操作
```

- **標題最重要**：越接近同事實際會問的口語句子越好，越容易被搜到。
- **memory_type**（可選）：客觀事實/規章 → `reference`；流程步驟 → `document`；備忘/踩坑 → `note` / `observation`。
- **tags**：給 2~3 個（如 `營運知識, 客服sop`），純粹方便日後分類過濾，不影響搜尋。

## 🔍 訪問資料（問魔鏡）

- **一般查詢**：像問人一樣自然發問即可。
  例：「GmPay 帳號怎麼更新到後台？」「vworld 測試站代理後台網址？」
- **清單型查詢**（「有哪些 X」「X 清單」「所有 X」）：這種要**完整列舉一整類**，靠分類 tag 撈，別只靠語意搜前幾筆——容易漏項。先找該分類的「清單/導航」記憶當範圍，再逐項展開。
- **管道**：把魔鏡 MCP 串接到 Claude Code / Claude Desktop 後，直接請 Claude 幫你查（例：「魔鏡有沒有關於 XX 的記憶？」）；或用之後的網頁查詢介面。

## 🚀 怎麼寫得更好（提高命中率）

| 做法 | 為什麼 |
|---|---|
| 標題用**口語問句**、多個問法用 `/` 隔開 | 越貼近真實問法，語意越接近，越搜得到 |
| 補**同義詞**（統編/統一編號、電話/市話/聯絡電話） | 別人換句話問也能命中 |
| **一則記憶只講一個主題** | 主題混在一起會稀釋語意、互相干擾 |
| 批次寫多筆時，順手做一筆**「XX 清單」導航記憶** | 清單型查詢才不會漏項 |
| 少用**純表格 / 純符號條列**，多用完整句子 | 結構化文字遠離口語向量，命中率低 |
| **帳密不要寫進去** → 改成「請查 ○○ 帳密表」+ 連結 | 資安；魔鏡只記「去哪拿」，不保管密碼 |
| 搜不到就**重寫得更口語、加同義詞、重存** | 命中率是調出來的，不是一次到位 |
